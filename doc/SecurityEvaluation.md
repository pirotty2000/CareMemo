# 『CareMemo』個人情報保護およびセキュリティ実装評価報告書（完全版）

## 1. エグゼクティブサマリー
本アプリケーションのセキュリティ実装状況を再検証しました。前回指摘した主要なリスク（データベースの平文保存、バックアップの未保護、デバッグログの残存）は技術的に解消されています。

「インターネット権限を持たない完全オフライン設計」を堅持しつつ、商用レベルの暗号化基盤を導入したことは高く評価できます。一方で、データの外部共有（PDF/ZIP）における運用上のリスクは依然として残っており、これらはシステムではなく「組織のルール」で補完する必要があります。

**判定：業務利用を条件付きで許可（強く推奨）**

---

## 2. 評価済みの主要なセキュリティ実装

### 2.1 物理的なデータ漏洩防止（新規対策）
*   **データベース暗号化 (SQLCipher)**: `AES-256` による Room DB 全体の透過的暗号化を確認。
*   **鍵管理 (Android Keystore)**: 暗号化鍵は `EncryptedSharedPreferences` を介してハードウェア隔離領域で保護。
*   **バックアップ保護 (Zip4j)**: エクスポート時に強制的に `AES` 暗号化を適用し、パスワード保護。
*   **ログ・ストリップ**: R8/ProGuard による `Log.d/v/i` のバイナリレベルでの除去。

### 2.2 権限の最小化と委譲モデル（継続評価）
*   **ネットワーク遮断**: `INTERNET` 権限を非保持。コードによる外部通信が不可能。
*   **権限委譲 (FileProvider)**: ストレージ全体へのアクセス権限を要求せず、`FileProvider` を介して必要なファイルのみを一時的に他アプリへ委譲する安全な設計。
*   **カメラ・音声の分離**: 標準インテントを介したOS標準アプリへの委譲により、本アプリがメディアキャプチャ権限を永続的に保持しない。

### 2.3 デバイス上のプライバシー保護（継続評価）
*   **画面キャプチャ防止**: `FLAG_SECURE` 実装により、録画やタスク履歴での内容露出を遮断。
*   **メディア保護**: 写真保存時に Exif 情報（GPS/日時等）を自動削除。
*   **生体認証**: アプリ起動、タイムアウト復帰、機密設定変更時のバイオメトリクス認証の統合。

## 3. 【忖度なし】残存する懸念事項とリスク評価

技術的対策が進んだ現在、以下の「プラットフォームおよび運用の限界」がリスクとして識別されます。

### 3.1 デバイスのルート化/Jailbreakに伴うリスク
*   **懸念**: 端末がルート化された場合、Keystore への物理アクセスやメモリダンプにより、暗号化がバイパスされる可能性がある。
*   **対策**: 組織としてルート化された端末での利用を禁止する MDM（モバイルデバイス管理）の導入を推奨。

### 3.2 共有機能（Intent）による「情報の出口」リスク
*   **懸念**: PDF出力時、宛先アプリの制限（White List）がない。誤って個人用メールやクラウドストレージを選択した場合、暗号化の保護範囲外にデータが流出する。
*   **評価**: マスキング（伏せ字）は強制適用されるが、情報そのものが外部へ渡る点は運用の脆弱性。

### 3.3 バックアップパスワードの強度依存
*   **懸念**: 暗号化ZIPの強度はユーザーが設定するパスワードに完全に依存する。「1234」等の脆弱なパスワードが設定された場合、暗号化の意味をなさない。
*   **評価**: システム側でパスワードポリシー（桁数・文字種）の強制実装が望ましい。

### 3.4 画面オーバーレイ攻撃への耐性
*   **懸念**: 悪意のある他アプリが画面上に不可視のレイヤーを重ねることで、入力を盗み見る「タップジャッキング」等の攻撃に対する防御実装が明示されていない。

## 4. 業務利用における遵守条件（セキュリティポリシー）
本アプリを業務で利用する際は、以下のルールを徹底すること。

1.  **認可アプリへの共有限定**: PDFおよびZIPの共有先は、組織が認可した業務用アプリ（法人用Slack、Teams、専用フォルダ等）に限定すること。
2.  **パスワードの独立性**: バックアップパスワードは、端末のアンロック番号や他のサービスと同一にせず、8文字以上の英数字混合を設定すること。
3.  **OSセキュリティの維持**: Keystore の脆弱性を突く攻撃を防ぐため、OSおよびセキュリティアップデートを「最新から1ヶ月以内」に適用すること。

## 5. 最終結論
本アプリは、開発段階からセキュリティを最優先しており、Android アプリケーションとして到達可能な最高レベルの保護策が講じられています。3節で挙げた懸念事項は、主に Android プラットフォーム全体に共通する課題であり、運用ルールの徹底によって許容可能な範囲内に管理できます。

よって、社内規定に則り、介護・医療現場での機密情報を扱う業務利用を承認します。
