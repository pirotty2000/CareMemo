### 🛠 移行ロードマップ (フェーズ別タスク)

#### フェーズ1：バックアップ構造の分離（準備）
- [x] **Backup DTO の導入**: `CareMemoBackup` から Entity を切り離し、`Int` 型を維持したバックアップ専用クラスを作成する。
- [x] **変換ロジックの実装**: `Entity` ⇄ `BackupDto` のマッピング関数を実装する。
- [x] **既存データの退避**: 構造変更前に、現行形式でのフルバックアップを確実に実施・検証する。

#### フェーズ2：データベースの UUID 化（実装）
- [x] **Entity の定義変更**: 全ての主キーおよび外部キーを `Int` から `String (UUID)` へ変更する。
- [x] **Room Migration の実装**: 既存のローカル DB データを `Int` から文字列へ移行するスクリプトを作成する。
- [x] **アプリ全体の型修正**: ViewModel, Repository, Logic 各層での ID 型変更に伴うコンパイルエラーを解消する。

#### フェーズ3：旧形式インポート・リマッピング（救済）
- [x] **IDリマッパーの実装**: `Int` (旧) → `UUID` (新) の紐付けをメモリ上で保持する `Map` 処理を実装する。
- [x] **旧形式ブリッジの構築**: フェーズ1で作った DTO を使い、旧形式バックアップを新 DB へ自動変換して取り込む機能を実装する。
- [x] **写真リンクの整合性確保**: ID 変更に伴う写真ファイル名とのリンク不整合を解決する。

#### フェーズ4：サーバー同期基盤の完成（拡張）
- [x] **Backup DTO の UUID 化**: バックアップ JSON 内の ID も UUID (String) で保持するよう DTO の型を修正する。
- [x] **更新日時 (updated_at) の追加**: 全 Entity に UTC ベースの最終更新日時カラムを追加する。
- [x] **同期制御フラグの導入**: サーバー送信済み・未送信を管理するフラグを追加する。
- [ ] **通信例外のハンドリング**: `AppException` にリモートエラー系を追加し、UI への通知基盤を整える。
