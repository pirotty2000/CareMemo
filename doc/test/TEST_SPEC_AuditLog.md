# テスト仕様書 - AuditLog (操作ログ)

- **対象テストコード:**
    - `app/src/androidTest/java/jp/mydns/fujiwara/carememo/ui/screens/settings/AuditLogScreenTest.kt`
    - `app/src/test/java/jp/mydns/fujiwara/carememo/data/repository/AuditLogRepositoryTest.kt`

## 1. コンポーネント単体テスト (AuditLogScreen)
**目的:** 操作ログ画面の各要素が正しく表示され、データの有無に応じた表示切り替えが機能することを検証する。

| ID    | テスト項目       | 検証内容                                                                                |
|:------|:------------|:------------------------------------------------------------------------------------|
| CP-01 | 基本レイアウト表示   | タイトル「操作ログ」と戻るボタンが表示されていること。                                                         |
| CP-02 | ログなし状態の表示   | 記録が1件もない時、専用の空状態（EmptyState）メッセージが表示されること。                                          |
| CP-03 | ログリスト表示     | ログが存在する場合、カード形式のリスト（AuditLogItem）で表示され、各項目に「機能名（日本語）」「操作種別」「結果ラベル（成功/失敗）」が含まれていること。 |
| CP-04 | フィルター・ソートバー | 結果絞り込み・機能絞り込みのチップ、および並び替えトグルボタンが表示されていること。                                          |
| CP-05 | 検索結果なし表示    | フィルター条件に一致するログがない時、「条件に合うログはありません」と表示されること。                                         |

## 2. 画面全体の挙動・結合テスト (AuditLogScreen)
**目的:** 絞り込み操作や並び替え、ナビゲーションが正しく ViewModel と連動することを検証する。

| ID    | テスト項目    | 検証内容                                                                       |
|:------|:---------|:---------------------------------------------------------------------------|
| BH-01 | 結果絞り込み操作 | 結果フィルターをタップしてドロップダウンを開き、項目（成功等）を選択した際に ViewModel のフィルター処理が呼ばれること。          |
| BH-02 | 機能絞り込み操作 | 機能フィルターをタップしてドロップダウンを開き、項目を選択した際に ViewModel のフィルター処理が呼ばれること。               |
| BH-03 | フィルター解除  | 解除ボタン（×）をタップした際、全ての絞り込み条件（結果・機能）がクリアされること。                                 |
| BH-04 | 戻る操作     | 戻るボタンをタップした際、`onBack` コールバックが呼ばれること。                                       |
| BH-05 | ラベルの日本語化 | マッパーにより、機能名（`PersonHealth` → `健康記録`）や結果種別（`SUCCESS` → `成功`）が日本語で表示されていること。 |
| BH-06 | 並び替え操作   | 並び替えトグルをタップした際、ViewModel の `toggleSortOrder` が呼ばれ、リストの昇順/降順が切り替わること。       |

## 3. ロジック・安全性テスト (AuditLogRepository)
**目的:** ログ記録の失敗がアプリ全体の動作に影響を及ぼさないことを検証する。

| ID    | テスト項目   | 検証内容                                                                 |
|:------|:--------|:---------------------------------------------------------------------|
| LG-01 | 例外保護    | ログ記録時に例外（DBエラー等）が発生しても、呼び出し元に例外を投げず正常終了すること。                         |
| LG-02 | 非同期安全性  | `NonCancellable` により、コルーチンがキャンセルされてもログの書き込みが試行されること。                 |
| LG-03 | 結果種別の記録 | 記録時に `resultType` (SUCCESS / DB_ERROR / OTHER_ERROR) が正しく指定・保存されること。 |

## 4. テスト用タグ (testTag) 定義
- `AuditLog_BackButton`: 戻るボタン
- `AuditLog_ResultFilter`: 結果絞り込みチップ
- `AuditLog_FeatureFilter`: 機能絞り込みチップ
- `AuditLog_SortToggle`: 並び替えトグルボタン
- `AuditLog_FilterClear`: フィルター解除ボタン
- `AuditLog_EmptyState`: 空状態表示
- `AuditLog_List`: ログ一覧（LazyColumn）
- `AuditLogItem_{id}`: 各ログ項目
