# テスト仕様書 - PersonConditionViewModel

- **対象テストコード:**
    - `app/src/test/java/jp/mydns/fujiwara/carememo/viewmodel/PersonConditionViewModelTest.kt`

## 1. 概要
所見メモ画面（SCR-PC-001）における UI 状態（UiState）の管理、テキスト入力、写真撮影・プレビュー連携、およびデータ保存の実行制御を検証する。
特に、編集セッションの状態遷移、写真データの動的購読、およびエラー発生時の安全性（監査ログ記録）を対象とする。

## 2. 初期化・データロードテスト (Initialization)
**目的:** 画面起動時や利用者切り替え時に、正しくデータ購読が開始され、初期状態がセットされることを検証する。

| ID     | テスト項目   | 検証内容                                            | 期待結果                                   |
|:-------|:--------|:------------------------------------------------|:---------------------------------------|
| INI-01 | 自動ロード成功 | `personId` 引数付きで起動                              | 指定した利用者の所見リストおよび写真有無マップが自動ロードされること     |
| INI-02 | 検索クエリ継承 | `Destination.ConditionDetail` の `query` 引数ありで起動 | `searchQuery` にセットされ、リストが初期状態で絞り込まれること |
| INI-03 | 撮影後復帰   | `Destination.PhotoPreview` からの復帰                | `previewUri` がセットされ、対象のレコードが選択状態になること  |

## 3. 選択・検索管理テスト (Selection & Search)
**目的:** レコード選択やキーワード検索に伴う UI 状態の連動が正しく行われることを検証する。

| ID     | テスト項目     | 条件 (操作)                              | 期待結果 (UiState)                                     |
|:-------|:----------|:-------------------------------------|:---------------------------------------------------|
| SEL-01 | レコード選択    | 既存レコード ID を `setSelectedConditionId` | 選択 ID が更新され、紐付く写真リストの購読が開始されること                    |
| SEL-02 | 検索キーワード更新 | `updateSearchQuery("キーワード")` を実行     | `searchQuery` が更新され、`filteredRecords` が即座に絞り込まれること |
| SEL-03 | 選択解除      | `setSelectedConditionId(null)` を実行   | 選択状態および編集入力がリセットされること                              |

## 4. 編集セッション管理テスト (Editing)
**目的:** 新規作成・編集モードの開始、入力変更、および保存ボタンの活性制御を検証する。

| ID     | テスト項目     | 条件 (操作)                             | 期待結果                                                         |
|:-------|:----------|:------------------------------------|:-------------------------------------------------------------|
| EDT-01 | 新規セッション開始 | ID="NEW" を `setSelectedConditionId` | 編集モードが開始され、デフォルト記録者がセットされること                                 |
| EDT-02 | 既存編集開始    | `startEditSession()` を実行            | 選択中のレコード内容が `editInput` にコピーされ、編集モードになること                    |
| EDT-03 | 入力変更と保存制御 | `updateEditInput` で値を変更             | `isChanged` が true になり、有効な入力時のみ `isSaveEnabled` が true になること |
| EDT-04 | 編集キャンセル   | `cancelEditSession()` を実行           | 編集モードが終了し、状態が破棄（または閲覧モードへ戻る）されること                            |

## 5. 処理実行テスト (Execution)
**目的:** 保存・削除・写真操作がリポジトリと正しく連携し、成功時に通知が行われることを検証する。

| ID     | テスト項目    | 条件                          | 期待結果                                                |
|:-------|:---------|:----------------------------|:----------------------------------------------------|
| EXE-01 | 所見メモ保存成功 | 有効な入力で `saveCurrentEdit()`  | リポジトリの `saveConditionAtVisit` が呼ばれ、成功イベントが発行されること |
| EXE-02 | 写真保存成功   | `processAndSavePhoto()` を実行 | `ImageUtils` での加工後に ViewModel で ID が割り当てられ、リポジトリへ登録されること |
| EXE-03 | 写真削除成功   | `deletePhoto()` を実行         | リポジトリの削除と `ImageUtils` による物理ファイル削除が両方呼ばれること         |

## 6. 安全性・例外テスト (Safety)
**目的:** 通信エラーやバリデーション失敗時に、UI 状態が適切に保たれ、ログが記録されることを検証する。

| ID     | テスト項目     | 条件                          | 期待結果                                       |
|:-------|:----------|:----------------------------|:-------------------------------------------|
| ERR-01 | ロード失敗     | 所見リストの Flow が例外をスロー         | `isLoading` が解除され、監査ログに `ERROR` が記録されること   |
| ERR-02 | 保存バリデーション | 本文空の状態で `saveCurrentEdit()` | 処理が中断され、`AppValidationException` がスローされること |
| ERR-03 | 保存失敗      | リポジトリ保存中に例外が発生              | `isLoading` が解除され、監査ログに `ERROR` が記録されること   |
