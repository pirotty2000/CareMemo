# テスト仕様書 - PersonHealthViewModel

- **対象テストコード:**
    - `app/src/test/java/jp/mydns/fujiwara/carememo/viewmodel/PersonHealthViewModelTest.kt`

## 1. 概要
健康記録画面（SCR-PH-001）における UI 状態（UiState）の管理、各カテゴリ（身長体重、バイタル、血糖）のデータロード、保存・更新、およびグラフ表示設定の管理を検証する。
特に、複数カテゴリの動的な切り替え、編集セッションの状態遷移、および前回の身長データの自動継承ロジックを対象とする。

## 2. 初期化・データロードテスト (Initialization)
**目的:** 画面起動時や利用者切り替え時に、正しくデータ購読が開始され、初期状態がセットされることを検証する。

| ID     | テスト項目    | 検証内容                               | 期待結果                                      |
|:-------|:---------|:-----------------------------------|:------------------------------------------|
| INI-01 | 自動ロード成功  | `personId` 引数付きで起動                 | 指定した利用者の基本情報および選択されたカテゴリの履歴リストがロードされること   |
| INI-02 | カテゴリ指定起動 | `categoryName` 引数付きで起動             | 指定されたカテゴリ（例: `BP_AND_PULSE`）が初期状態で選択されること |
| INI-03 | 表示設定の反映  | `healthDisplayModeIsHistory` 設定の変更 | UI 状態の `preferredShowHistory` に即座に反映されること |

## 3. カテゴリ・状態管理テスト (Category & State)
**目的:** カテゴリ切り替えや表示設定の変更が、UI 状態およびデータ取得 Flow と正しく連動することを検証する。

| ID     | テスト項目    | 条件 (操作)                            | 期待結果 (UiState)                                       |
|:-------|:---------|:-----------------------------------|:-----------------------------------------------------|
| CAT-01 | カテゴリ切り替え | `setCategory(newCategory)` を実行     | `currentCategory` が更新され、該当カテゴリのリポジトリ Flow 購読が開始されること |
| CAT-02 | 表示モード変更  | `updatePreferredShowHistory(true)` | リポジトリの設定変更メソッドが呼ばれること                                |
| CAT-03 | 選択解除     | `setSelectedRecordId(null)` を実行    | 選択状態および編集入力がリセットされること                                |

## 4. 編集セッション管理テスト (Editing)
**目的:** 新規作成・編集モードの開始、入力変更、および保存ボタンの活性制御を検証する。

| ID     | テスト項目     | 条件 (操作)                          | 期待結果                                                         |
|:-------|:----------|:---------------------------------|:-------------------------------------------------------------|
| EDT-01 | 新規セッション開始 | ID="NEW" を `setSelectedRecordId` | 編集モードが開始され、日時に現在時刻がセットされること                                  |
| EDT-02 | 身長データの継承  | 身長体重カテゴリで新規セッション開始               | 前回の記録がある場合、最新の身長値が `heightText` に自動セットされること                  |
| EDT-03 | 既存編集開始    | `startEditSession()` を実行         | 選択中のレコード内容が `editInput` にコピーされ、編集モードになること                    |
| EDT-04 | 入力変更と保存制御 | `updateEditInput` で値を変更          | `isChanged` が true になり、有効な入力時のみ `isSaveEnabled` が true になること |

## 5. 処理実行テスト (Execution)
**目的:** 保存・削除操作がリポジトリと正しく連携し、重複チェックや成功時の通知が行われることを検証する。

| ID     | テスト項目    | 条件                         | 期待結果                                                                 |
|:-------|:---------|:---------------------------|:---------------------------------------------------------------------|
| EXE-01 | 保存成功(新規) | 有効な入力で `saveCurrentEdit()` | リポジトリの `insert` が呼ばれ、成功イベントとスナックバーが表示されること                           |
| EXE-02 | 重複チェック   | 同一日時の既存データが存在する状態で保存       | 保存が中断され、重複エラー通知（R.string.common_err_duplicate_blocked_simple）が行われること |
| EXE-03 | 物理削除成功   | `deleteRecord(item)` を実行   | リポジトリの該当カテゴリの削除メソッドが呼ばれること                                           |

## 6. 安全性・例外テスト (Safety)
**目的:** エラー発生時に UI 状態が適切に保たれ、監査ログが記録されることを検証する。

| ID     | テスト項目 | 条件                | 期待結果                                     |
|:-------|:------|:------------------|:-----------------------------------------|
| ERR-01 | ロード失敗 | 履歴取得 Flow が例外をスロー | `isLoading` が解除され、監査ログに `ERROR` が記録されること |
| ERR-02 | 保存失敗  | リポジトリ保存中に例外が発生    | `isLoading` が解除され、監査ログに `ERROR` が記録されること |

## 7. ナビゲーションテスト (Navigation)
**目的:** 画面遷移等の副作用（ViewEvent）が正しく発行されることを検証する。

| ID     | テスト項目   | 操作                              | 期待結果                                               |
|:-------|:--------|:--------------------------------|:---------------------------------------------------|
| NAV-01 | グラフ拡大遷移 | `navigateToGraphExpansion(...)` | `viewEvent` から `NavigateToGraphExpansion` が発行されること |
