# テスト仕様書 - BatchInputViewModel

- **対象テストコード:**
    - `app/src/test/java/jp/mydns/fujiwara/carememo/viewmodel/BatchInputViewModelTest.kt`

## 1. 概要
健康記録の一括入力画面（SCR-PH-002）における UI 状態（UiState）の管理、複数カテゴリにわたるデータの保存処理、および画面遷移イベントの正確性を検証する。
特に、複数カテゴリの保存原子性と、同一日時における重複チェックロジックを対象とする。

## 2. 初期化・データロードテスト (Initialization)
**目的:** 画面起動時に正しく利用者情報がロードされ、UI 状態が初期化されることを検証する。

| ID     | テスト項目   | 検証内容                         | 期待結果                                      |
|:-------|:--------|:-----------------------------|:------------------------------------------|
| INI-01 | 自動ロード成功 | `personId` 引数付きで起動           | 指定した利用者の情報が取得され、入力項目が空で初期化されること           |
| INI-02 | 伏せ字設定反映 | `isNameMaskingEnabled` 設定の変更 | UI 状態の `isNameMaskingEnabled` に即座に反映されること |

## 3. 入力・状態管理テスト (Input & State)
**目的:** 各項目の入力や日時の変更に対して、UI 状態が反応的（Reactive）に更新されることを検証する。

| ID     | テスト項目   | 条件 (操作)                  | 期待結果 (UiState)                                          |
|:-------|:--------|:-------------------------|:--------------------------------------------------------|
| INP-01 | 数値入力と反応 | `updateWeight("60")` を実行 | `weight` が更新され、`isChanged` と `isValid` が true になること     |
| INP-02 | 日時変更    | `updateYear(year)` 等を実行  | `year` 等が更新され、`recordTime` および `isChanged` が true になること |
| INP-03 | 利用者切り替え | 異なる `personId` で再ロード     | 以前の入力値が全てクリアされ、日時に現在時刻がセットされること                         |

## 4. 一括保存テスト (Batch Saving)
**目的:** 保存処理の正確性、重複チェックの堅牢性、およびエラー発生時の安全性を検証する。

| ID     | テスト項目      | 条件                       | 期待結果                                                             |
|:-------|:-----------|:-------------------------|:-----------------------------------------------------------------|
| SAV-01 | 保存成功(単一)   | 体重のみ入力して `saveBatch()`   | リポジトリの `saveHealthDataBatch` が呼ばれ、入力がクリアされること                    |
| SAV-02 | 保存成功(複合)   | 体重と血圧を入力して `saveBatch()` | 2 カテゴリ分の Entity が生成され、一括保存が実行されること                               |
| SAV-03 | バリデーションエラー | 形式不正な値を入力して保存試行          | 保存が中断され、適切なエラーログ（VALIDATION_ERROR）が記録されること                       |
| SAV-04 | 重複ブロック     | 同一日時の既存データが存在する状態で保存     | リポジトリの `findHistoryRecordAtTime` で重複が検出され、重複カテゴリ名を含むエラー通知が行われること |
| SAV-05 | 保存失敗時の安全性  | リポジトリで例外が発生              | `isLoading` が解除され、監査ログに `ERROR` が記録されること                         |

## 5. ナビゲーションテスト (Navigation)
**目的:** UI 操作に伴う副作用（ViewEvent）が正しく発行されることを検証する。

| ID     | テスト項目 | 操作                     | 期待結果                                   |
|:-------|:------|:-----------------------|:---------------------------------------|
| NAV-01 | 戻る操作  | `navigateBack()` を呼び出し | `viewEvent` から `NavigateBack` が発行されること |

## 6. 状態復元テスト (State Restoration)
**目的:** プロセス死（Process Death）からの復元において、一括入力中の多数の項目や日時設定が正しく維持されることを検証する。

| ID     | テスト項目       | 検証内容                               | 期待結果                                           |
|:-------|:------------|:-----------------------------------|:-----------------------------------------------|
| RST-01 | 全入力項目の復元    | `SavedStateHandle` に各数値と日時がある状態で起動 | 各カテゴリの数値、および日時（年月日時分）が UI 状態に復元されること           |
| RST-02 | 変更検知基準の復元   | `SavedStateHandle` に初期日時がある状態で起動   | 復元された初期日時と現在の入力日時が比較され、`isChanged` が正しく算出されること |
| RST-03 | ロード時のリセット防止 | 復元起動かつ利用者データのロード完了時                | 復元された入力値が、初期化処理（現在時刻へのリセット等）で上書きされず維持されること     |

## 7. バリデーション・フィードバックテスト (Validation Feedback)
**目的:** 健康記録の数値入力や日時の不備に対して、具体的なガイドメッセージが設定されることを検証する。

| ID     | テスト項目        | 条件                                     | 期待結果                                                                          |
|:-------|:-------------|:---------------------------------------|:------------------------------------------------------------------------------|
| FBK-01 | 数値範囲外フィードバック | 体温に「45.0」を入力し `markFieldAsTouched` を実行 | `fieldErrors` に範囲外エラー、`fieldErrorArgs` に「34.0」「43.0」がセットされること                 |
| FBK-02 | 形式不正フィードバック  | 血圧に「12.3.4」など数値を入力                     | `fieldErrors` に形式不正エラー（R.string.common_error_invalid_input）がセットされること          |
| FBK-03 | 未来日時フィードバック  | 記録日時に未来の日時をセット                         | `fieldErrors` に未来日禁止エラー（R.string.common_err_future_date_not_allowed）がセットされること |
| FBK-04 | 操作前エラーの抑制    | 項目が空だが `touchedFields` に含まれない場合        | `fieldErrors` が null であること（初期表示時にいきなり赤くならないこと）                                |
