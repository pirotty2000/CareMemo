# テスト仕様書 - PersonEditViewModel

- **対象テストコード:**
    - `app/src/test/java/jp/mydns/fujiwara/carememo/viewmodel/PersonEditViewModelTest.kt`

## 1. 概要
利用者の基本情報（氏名、ふりがな、生年月日、備考）の登録・編集画面における UI 状態（UiState）の管理、バリデーション、保存処理の実行制御、および画面遷移イベントの正確性を検証する。

## 2. 初期化・データロードテスト (Initialization)
**目的:** 画面起動時のモード判定（新規・編集）および初期データのロードが正しく行われることを検証する。

| ID     | テスト項目     | 検証内容                               | 期待結果                                              |
|:-------|:----------|:-----------------------------------|:--------------------------------------------------|
| INI-01 | 新規登録モード起動 | `personId = "_new"` (または null) で起動 | `isNew = true` となり、各入力フィールドが空で初期化されること            |
| INI-02 | 既存編集モード起動 | 有効な `personId` で起動                 | `isNew = false` となり、リポジトリから取得した情報が各フィールドにセットされること |
| INI-03 | 伏せ字設定反映   | `isNameMaskingEnabled` 設定の変更       | UI 状態の `isNameMaskingEnabled` に即座に反映されること         |

## 3. 入力・状態管理テスト (Input & State)
**目的:** 各項目の入力変更に対して、UI 状態および派生状態（isChanged, isValid）が反応的に更新されることを検証する。

| ID     | テスト項目          | 条件 (操作)               | 期待結果 (UiState)                        |
|:-------|:---------------|:----------------------|:--------------------------------------|
| INP-01 | 名前入力と変更検知      | `updateLastName` 等を実行 | 該当フィールドが更新され、`isChanged = true` になること |
| INP-02 | 生年月日入力とバリデーション | 有効な和暦（年・月・日）を入力       | `isValid = true` (他の必須項目入力済み時) になること  |
| INP-03 | 入力値の正規化 (原子性)  | フィールド更新直後の状態確認        | 入力値の反映と `isChanged` 等の更新が原子的に行われること   |

## 4. 保存・処理実行テスト (Saving)
**目的:** 保存処理の正確性、重複チェックの挙動、および成功時の遷移イベントを検証する。

| ID     | テスト項目       | 条件                      | 期待結果                                                             |
|:-------|:------------|:------------------------|:-----------------------------------------------------------------|
| SAV-01 | 新規保存成功      | 有効な入力で `save()` (新規モード) | `personRepository.insertPerson` が呼ばれ、`ADDED` 結果で戻るイベントが発行されること   |
| SAV-02 | 更新保存成功      | 有効な入力で `save()` (編集モード) | `personRepository.updatePerson` が呼ばれ、`UPDATED` 結果で戻るイベントが発行されること |
| SAV-03 | 重複検出(アクティブ) | 同姓同名・同生年月日の有効な利用者が存在    | 保存が中断され、重複エラー通知（R.string.main_err_duplicate_active）が行われること       |
| SAV-04 | 重複検出(アーカイブ) | 同姓同名・同生年月日の終了した利用者が存在   | 保存が中断され、復帰を促すエラー通知（R.string.main_err_duplicate_archived）が行われること  |

## 5. 安全性・例外テスト (Safety)
**目的:** エラー発生時に UI 状態が適切に保たれ、監査ログが記録されることを検証する。

| ID     | テスト項目     | 条件                    | 期待結果                                      |
|:-------|:----------|:----------------------|:------------------------------------------|
| ERR-01 | ロード失敗     | 初期データ取得 Flow が例外をスロー  | `isLoading` が解除され、監査ログに `ERROR` が記録されること  |
| ERR-02 | バリデーション失敗 | 必須項目未入力で `save()` を強行 | 処理が中断され、監査ログに `VALIDATION_ERROR` が記録されること |
| ERR-03 | 保存失敗      | リポジトリ保存中に例外が発生        | `isLoading` が解除され、監査ログに `ERROR` が記録されること  |
