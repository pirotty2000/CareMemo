# テスト仕様書 - PersonDetailUiStateViewModel

- **対象テストコード:**
    - `app/src/test/java/jp/mydns/fujiwara/carememo/viewmodel/PersonDetailUiStateViewModelTest.kt`

## 1. 概要
利用者詳細画面（共通フレームワーク）における、利用者情報の共有、カテゴリ（健康記録・所見・服薬）の切り替え管理、および共通 UI イベントの正確性を検証する。
特に、`SavedStateHandle` からの引数取得と、カテゴリ変更に伴う UI 状態の連動を対象とする。

## 2. 初期化・データロードテスト (Initialization)
**目的:** 画面起動時に正しく引数が処理され、利用者情報およびカテゴリがセットされることを検証する。

| ID     | テスト項目     | 検証内容                   | 期待結果                                      |
|:-------|:----------|:-----------------------|:------------------------------------------|
| INI-01 | 自動ロード成功   | `personId` 引数付きで起動     | 指定した利用者の情報（氏名等）および記録サマリーがロードされること         |
| INI-02 | 初期カテゴリ指定  | `categoryName` 引数付きで起動 | 指定されたカテゴリ（例: `BP_AND_PULSE`）が初期状態で選択されること |
| INI-03 | 不正カテゴリの回避 | 無効なカテゴリ名で起動            | デフォルトカテゴリ (`HEIGHT_AND_WEIGHT`) が維持されること  |

## 3. カテゴリ管理テスト (Category Management)
**目的:** 画面内のカテゴリ切り替え操作が、UI 状態およびイベントとして正しく反映されることを検証する。

| ID     | テスト項目      | 条件 (操作)                           | 期待結果 (UiState / ViewEvent)                   |
|:-------|:-----------|:----------------------------------|:---------------------------------------------|
| CAT-01 | カテゴリ変更(内部) | `setCategory(newCategory)` を実行    | `uiState.currentCategory` が即座に更新されること        |
| CAT-02 | カテゴリ遷移要求   | `navigateToCategory(newCategory)` | `viewEvent` から `NavigateToCategory` が発行されること |

## 4. ナビゲーションテスト (Navigation)
**目的:** 共通的な画面遷移要求（一覧へ戻る等）が正しく送出されることを検証する。

| ID     | テスト項目 | 操作                           | 期待結果                                         |
|:-------|:------|:-----------------------------|:---------------------------------------------|
| NAV-01 | 戻る操作  | `navigateBackToMain()` を呼び出し | `viewEvent` から `NavigateBackToMain` が発行されること |

## 5. 安全性・例外テスト (Safety)
**目的:** データ読み込み失敗時に、UI 状態が適切に保たれ、ログが記録されることを検証する。

| ID     | テスト項目 | 条件                   | 期待結果                                       |
|:-------|:------|:---------------------|:-------------------------------------------|
| ERR-01 | ロード失敗 | 利用者情報取得 Flow が例外をスロー | `isLoading` が解除され、監査ログに `ERROR` が記録されること   |
| ERR-02 | 準備ロード | `loadPerson` 開始時     | 以前の利用者のデータがクリア（`onPrepareLoadPerson`）されること |
