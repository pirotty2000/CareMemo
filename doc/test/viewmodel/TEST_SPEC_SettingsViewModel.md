# テスト仕様書 - SettingsViewModel

- **対象テストコード:**
    - `app/src/test/java/jp/mydns/fujiwara/carememo/viewmodel/SettingsViewModelTest.kt`

## 1. 概要
アプリ設定画面（SCR-S-001）における UI 状態（UiState）の管理、ユーザー設定の同期および更新、バックアップ・復元等の重い処理の実行制御、および画面遷移イベントの正確性を検証する。
特に、複数リポジトリからの設定値統合、非同期処理中の進捗管理、およびエラー発生時の安全性（監査ログ記録）を対象とする。

## 2. 初期化・設定同期テスト (Initialization & Sync)
**目的:** 画面起動時に各リポジトリから最新の設定値および統計情報が正しくロードされ、UI 状態に反映されることを検証する。

| ID     | テスト項目     | 検証内容                         | 期待結果                                             |
|:-------|:----------|:-----------------------------|:-------------------------------------------------|
| INI-01 | 初期設定同期成功  | `SettingsViewModel` のインスタンス化 | 氏名伏せ字、テーマ、ログ保持期間等の全設定値が `UiState` に反映されること       |
| INI-02 | 統計情報のロード  | 監査ログ件数や終了利用者数の取得             | `auditLogCount` および `endedUserCount` が正しく反映されること |
| INI-03 | 同期失敗時の安全性 | 設定購読中に例外が発生                  | `isProcessing` が解除され、監査ログに `ERROR` が記録されること      |

## 3. 設定更新テスト (Settings Updates)
**目的:** UI 操作による各設定値の変更要求が、正しく `UserSettingsRepository` へ委譲されることを検証する。

| ID     | テスト項目     | 条件 (操作)                              | 期待結果                                  |
|:-------|:----------|:-------------------------------------|:--------------------------------------|
| SET-01 | 氏名伏せ字更新   | `setNameMaskingEnabled(true/false)`  | リポジトリの該当メソッドが呼ばれること                   |
| SET-02 | テーマ設定更新   | `setThemeSetting(ThemeSetting.DARK)` | リポジトリの該当メソッドが呼ばれること                   |
| SET-03 | ログ保持期間更新  | `setAuditLogRetentionDays(90)`       | リポジトリの該当メソッドが呼ばれること                   |
| DEV-01 | 開発者モード有効化 | バージョン情報を規定回数（7回）タップ                  | `isDeveloperModeEnabled` が true になること |

## 4. メンテナンス操作テスト (Maintenance Ops)
**目的:** バックアップ・復元、データ消去等の重要操作が正しく実行され、完了時に適切な通知が行われることを検証する。

| ID     | テスト項目      | 条件 (操作)                    | 期待結果                                               |
|:-------|:-----------|:---------------------------|:---------------------------------------------------|
| MNT-01 | データエクスポート  | `exportData(uri)` を実行      | リポジトリのエクスポートが呼ばれ、完了後に `ExportSuccess` イベントが発行されること |
| MNT-02 | データインポート   | `importData(uri)` を実行      | リポジトリのインポートが呼ばれ、完了後に `ImportSuccess` イベントが発行されること  |
| MNT-03 | パスワード要求    | インポート中にパスワードエラー発生          | `RequestImportPassword` イベントが発行されること               |
| MNT-04 | 全データ消去     | `clearAllData()` を実行       | リポジトリの全消去メソッドが呼ばれ、完了通知が表示されること                     |
| MNT-05 | 整合性チェック    | `checkIntegrity()` を実行     | 不整合レコードがスキャンされ、結果が `inconsistencies` に反映されること      |
| MNT-06 | 監査ログエクスポート | `exportAuditLogs(uri)` を実行 | リポジトリの監査ログエクスポートが呼ばれること                            |

## 5. 安全性・例外テスト (Safety)
**目的:** メンテナンス操作等の失敗時に、UI 状態が適切に復帰し、ログが記録されることを検証する。

| ID     | テスト項目     | 条件            | 期待結果                              |
|:-------|:----------|:--------------|:----------------------------------|
| ERR-01 | エクスポート失敗  | エクスポート中に例外が発生 | `isProcessing` が解除され、監査ログに記録されること |
| ERR-02 | 監査ログ全消去失敗 | ログ消去中に例外が発生   | `isProcessing` が解除され、監査ログに記録されること |

## 6. ナビゲーションテスト (Navigation)
**目的:** 設定項目からの画面遷移要求が、正しいイベントとして送出されることを検証する。

| ID     | テスト項目     | 操作                                     | 期待結果                                            |
|:-------|:----------|:---------------------------------------|:------------------------------------------------|
| NAV-01 | 監査ログ遷移    | `navigateToAuditLog()`                 | `SettingsViewEvent.NavigateToAuditLog` が発行されること |
| NAV-02 | アーカイブ管理遷移 | `navigateToArchiveManagement(RESTORE)` | 正しいモードを伴うイベントが発行されること                           |

## 7. バリデーション・フィードバックテスト (Validation Feedback)
**目的:** 設定入力値の不備に対して、適切なフィードバックが設定されることを検証する。

| ID     | テスト項目 | 条件 | 期待結果 |
|:-------|:----------|:----------------------|:------------------------------------------|
| FBK-01 | デフォルト記録者名超過 | 記録者名に51文字以上入力 | `fieldErrors` に名前超過エラーがセットされること |
| FBK-02 | バックアップパスワード不足 | パスワードに5文字以下を入力 | `fieldErrors` にパスワード不足エラーがセットされること |
