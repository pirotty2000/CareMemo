# テスト仕様書 - PersonListViewModel

- **対象テストコード:**
    - `app/src/test/java/jp/mydns/fujiwara/carememo/viewmodel/PersonListViewModelTest.kt`

## 1. 概要
利用者一覧画面（MainScreen）における UI 状態（UiState）の管理、多角的なフィルタリング（五十音順・経過記録検索）、利用者管理操作、および画面遷移イベントの正確性を検証する。
リポジトリ、検索結果、サマリー情報の動的な統合ロジックを対象とする。

## 2. 初期化・データロードテスト (Initialization)
**目的:** 画面起動時に正しくデータ購読が開始され、利用者情報、サマリー、設定値が統合されて反映されることを検証する。

| ID     | テスト項目   | 検証内容                           | 期待結果                                                   |
|:-------|:--------|:-------------------------------|:-------------------------------------------------------|
| INI-01 | 自動ロード成功 | `PersonListViewModel` のインスタンス化 | 全利用者リスト、記録サマリーが取得され、`userList` に加工済みデータが反映されること        |
| INI-02 | 伏せ字設定反映 | `isNameMaskingEnabled` 設定の変更   | UI 状態の `isNameMaskingEnabled` に即座に反映され、リストの氏名がマスクされること |

## 3. フィルタ・検索管理テスト (Filtering & Search)
**目的:** ユーザーのフィルタ操作に応じて、表示リストが正しく更新されることを検証する。

| ID     | テスト項目      | 条件 (操作)                       | 期待結果 (UiState)                                |
|:-------|:-----------|:------------------------------|:----------------------------------------------|
| FLT-01 | 五十音セクション変更 | `setSelectedSection("か")` を実行 | `selectedSection` が更新され、苗字が「か行」の利用者のみが表示されること |
| FLT-02 | 検索キーワード更新  | `setSearchQuery("キーワード")`     | `searchQuery` が更新され、自動的にセクションが「全」に切り替わること     |
| FLT-03 | 経過記録検索との統合 | 経過記録のキーワード検索結果がある状態           | 氏名不一致でも、記録内容が一致する利用者がリストに含まれること               |

## 4. クイックメニュー・詳細操作テスト (Quick Menu)
**目的:** 利用者ごとのメニュー表示や、緊急連絡先のオンデマンド取得を検証する。

| ID     | テスト項目    | 条件 (操作)                     | 期待結果                                                     |
|:-------|:---------|:----------------------------|:---------------------------------------------------------|
| MNU-01 | メニュー表示   | `showQuickMenu(person)` を実行 | 対象の利用者が保持され、`isQuickActionMenuExpanded` が true になること     |
| MNU-02 | 緊急連絡先ロード | `loadEmergencyContacts(id)` | メニューが閉じ、連絡先リストが取得され `emergencyContactsForSheet` に反映されること |
| MNU-03 | 連絡先なし    | 連絡先が 0 件の利用者をロード            | スナックバーで通知が行われ、ロード状態がリセットされること                            |

## 5. 利用者管理操作テスト (Management)
**目的:** 利用者の追加、論理削除、復元操作がリポジトリと正しく連携することを検証する。

| ID     | テスト項目    | 条件 (操作)                       | 期待結果                                        |
|:-------|:---------|:------------------------------|:--------------------------------------------|
| MGT-01 | 利用者追加    | `addPerson(person)` を実行       | リポジトリの `insertPerson` が呼ばれ、保存成功イベントが発行されること |
| MGT-02 | 重複追加ブロック | 既存利用者と重複する情報を追加               | 保存が中断され、重複エラーダイアログが表示されること                  |
| MGT-03 | 論理削除実行   | `logicalDeletePerson(person)` | リポジトリの論理削除メソッドが呼ばれ、スナックバーが表示されること           |
| MGT-04 | 復元実行     | `restorePerson(person)`       | リポジトリの復元メソッドが呼ばれ、スナックバーが表示されること             |

## 6. ナビゲーションテスト (Navigation)
**目的:** 各画面への遷移要求が、正しい引数とともに送出されることを検証する。

| ID     | テスト項目  | 操作                               | 期待結果                                     |
|:-------|:-------|:---------------------------------|:-----------------------------------------|
| NAV-01 | 詳細画面遷移 | `navigateToDetail(id, category)` | 現在の検索クエリを伴って `NavigateToDetail` が発行されること |
| NAV-02 | 一括入力遷移 | `navigateToBatchInput(id)`       | `NavigateToBatchInput` イベントが発行されること      |

## 7. 安全性・例外テスト (Safety)
**目的:** データ取得失敗時等に、UI 状態が適切に保たれ、監査ログが記録されることを検証する。

| ID     | テスト項目   | 条件                           | 期待結果                                     |
|:-------|:--------|:-----------------------------|:-----------------------------------------|
| ERR-01 | リスト取得失敗 | `getAllPersons` Flow が例外をスロー | `isLoading` が解除され、監査ログに `ERROR` が記録されること |
| ERR-02 | 連絡先取得失敗 | 連絡先取得中に例外が発生                 | 連絡先ローディング状態が解除され、監査ログに記録されること            |

## 8. 状態復元テスト (State Restoration)
**目的:** プロセス死（Process Death）からの復元後に、ユーザーの検索・絞り込み条件が維持されることを検証する。

| ID     | テスト項目       | 条件 (SavedStateHandle)            | 期待結果                                                     |
|:-------|:------------|:---------------------------------|:---------------------------------------------------------|
| RST-01 | 検索クエリの復元   | `search_query` が存在する状態で起動     | UI 状態の `searchQuery` に保存値が反映され、リストがフィルタされること |
| RST-02 | セクション選択復元 | `selected_section` が存在する状態で起動 | UI 状態の `selectedSection` に保存値が反映されること                |
| RST-03 | リストの再取得   | 復元起動時                        | `userList` は保存値ではなく、DB から最新のデータとして再ロードされること  |
