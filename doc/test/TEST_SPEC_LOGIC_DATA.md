# CareMemo テスト仕様書 (ロジック・データ層)

- **対象テストコード:**
    - `test/java/jp/mydns/fujiwara/carememo/data/` (AppThresholdsTest等)
    - `test/java/jp/mydns/fujiwara/carememo/viewmodel/` (PersonLifecycleTest等)
    - `test/java/jp/mydns/fujiwara/carememo/utils/` (DateTimeUtilsTest等)
    - `androidTest/java/jp/mydns/fujiwara/carememo/data/` (CareMemoDatabaseTest等)
    - `androidTest/java/jp/mydns/fujiwara/carememo/utils/` (ImageUtilsTest等)

このドキュメントは、CareMemo における「目に見えない部分（ロジック、データ整合性、非同期安全性）」を担保するために実装された自動テストの仕様をまとめたものです。
現在、合計 81 件のテストケース（Unit: 55件, Instrumented: 26件）が実装され、全て合格しています。

---

## 0. テストの方針
- **目的**: UI の変更に左右されない「アプリの心臓部」の正しさを機械的に保証する。
- **構成**:
    - **Unit Test (Local)**: 開発 PC 上で高速に実行されるロジック検証。
    - **Instrumented Test (Android)**: 実機・エミュレータ上の実DBやファイルシステムを用いた統合検証。

---

## 1. ビジネスロジック・ユーティリティ (Unit Test)
アプリ全体の計算ルールやデータ変換の正確性を検証します。

| テストファイル                 | 検証の目的                            | 防いでいるリスク                              |
|:------------------------|:---------------------------------|:--------------------------------------|
| `AppThresholdsTest.kt`  | 数値入力のバリデーション、BMI計算、バイタル等の判定ロジック。 | 入力形式の誤り、異常値の見落とし、判定基準の誤適用。            |
| `DateTimeUtilsTest.kt`  | 和暦、年齢計算、誕生日判定、生年月日の時刻正規化ロジック。    | 日付計算ミス、和暦表示の不備、**生年月日の時刻差による別人判定バグ。** |
| `CareMemoBackupTest.kt` | データの JSON シリアライズ・デシリアライズの完全性。    | バックアップデータの破損、復元時のデータ欠落（1ミリ秒の狂いもない復元）。 |

---

## 2. データ層・整合性 (Instrumented Test)
データベース (Room/SQLite) の制約や、データの関係性を検証します。

| テストファイル                           | 検証の目的                               | 防いでいるリスク                      |
|:----------------------------------|:------------------------------------|:------------------------------|
| `CareMemoDatabaseTest.kt`         | 物理削除の連鎖、一意制約(Upsert)、**カスケード論理削除**。 | 迷子データの残存、データの二重登録、論理削除の同期漏れ。  |
| `AppMaintenanceRepositoryTest.kt` | 全消去、リストアの一連の流れ。不整合データの検出・清掃。        | 機種変更時のデータ消失、DB構造の不整合によるアプリ停止。 |
| `UserSettingsRepositoryTest.kt`   | 設定値（DataStore）の永続化、テーマや伏せ字設定の即時反映。  | 設定が保存されない、再起動後に設定が先祖返りする不具合。  |

---

## 3. ビジネスプロセス・安全性 (Unit Test)
ViewModel を中心とした、画面の裏側での処理の流れを検証します。

| テストファイル                      | 検証の目的                                                                | 防いでいるリスク                                            |
|:-----------------------------|:---------------------------------------------------------------------|:----------------------------------------------------|
| `PersonLifecycleTest.kt`     | 利用者切り替え時の**状態即時クリア**、古い非同期処理のキャンセル。                                  | **前の利用者のデータが一瞬見える、レースコンディションによるデータ混在。**             |
| `PersonEditViewModelTest.kt` | **重複チェックと自己更新の判定ロジック**。4条件（姓名生年月日メモ）一致による保存ブロック、および自分自身の更新（ID一致）の許容。 | 同一人物の二重登録、および意図しない他者データとの衝突。**自分自身の情報を編集できなくなるバグ。** |
| `BatchInputViewModelTest.kt` | **記録日時の重複チェック**。既存データがあるカテゴリの保存ブロック。                                 | 一括入力画面での意図しない既存データの上書き・破壊。                          |
| `*RepositoryTest.kt`         | 各種データ保存時の**操作ログ (AuditLog)** の自動記録。                                  | 監査証跡の欠落、DAO への誤ったパラメータ渡し。                           |
| `Person*ViewModelTest.kt`    | 検索フィルタリング、写真紐付け、服薬の一括同期ロジック。                                         | 検索が効かない、写真が記録から外れる、服薬の削除漏れ。                         |

---

## 4. ファイル・リソース管理 (Instrumented Test)
ストレージ上の物理ファイルの管理を検証します。

| テストファイル             | 検証の目的                                  | 防いでいるリスク                                 |
|:--------------------|:---------------------------------------|:-----------------------------------------|
| `ImageUtilsTest.kt` | 写真・サムネイルの物理削除、**24時間経過した一時ファイルの自動掃除**。 | ストレージの肥大化、DBと物理ファイルの不整合（画像切れ）、放置ファイルの残存。 |

---

## 5. 実行方法
- **Unit Test**: Android Studio の `test` フォルダを右クリックし "Run 'Tests in...'" を実行。
- **Instrumented Test**: `androidTest` フォルダを右クリックし "Run 'Tests in...'" を実行（エミュレータまたは実機が必要）。
