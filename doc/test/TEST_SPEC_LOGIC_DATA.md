# テスト仕様書 - 基盤・整合性テスト (Foundation & Integrity)

- **対象テストルート:**
    - `app/src/test/java/jp/mydns/fujiwara/carememo/` (Unit Test)
    - `app/src/androidTest/java/jp/mydns/fujiwara/carememo/` (Instrumented Test)

## 1. 概要
このドキュメントは、CareMemo プロジェクトの屋台骨となる、データの破壊や不整合、ライフサイクルの競合を防ぐための最重要テストの技術仕様を定義します。
全体の戦略や機能別のテストインデックスについては、[TEST_MASTER_GUIDE.md](./TEST_MASTER_GUIDE.md) を参照してください。

---

## 2. データベース整合性検証 (DT-01)
**目的:** Room のスキーマ定義（外部キー、一意制約、インデックス）が設計通り機能し、データが保護されることを実機で検証する。
- **対象:** `CareMemoDatabaseTest.kt`, `CareMemoDaoTest.kt`

| ID       | テスト項目     | 検証内容                                | 期待結果                                         |
|:---------|:----------|:------------------------------------|:---------------------------------------------|
| DT_01_01 | 外部キー物理削除  | 利用者を物理削除 (`deletePersonPhysically`) | 紐付く全カテゴリの記録も連動して自動的に消えること                    |
| DT_01_02 | 一意制約(一般)  | 同一利用者・同一日時の記録登録                     | エラーにならず後勝ちで上書き(Upsert)されること                  |
| DT_01_03 | 一意制約(服薬)  | 同一日・同一時間枠の重複登録                      | 前回の記録が上書きされ、1件のみ維持されること                      |
| DT_01_04 | カスケード論理削除 | 利用者を論理削除 (`logicalDeletePerson`)    | Repository経由で全カテゴリの `deletedAt` が原子的に更新されること |
| DT_01_05 | サマリー整合性   | 論理削除されたレコードの集計                      | `hasHeightWeight` 等のフラグに論理削除済みデータが含まれないこと    |
| DT_01_06 | 監査ログ順序    | 複数のログを登録                            | 取得時に `timestamp` の降順（新しい順）でソートされていること        |

---

## 3. バックアップ完全性検証 (UT-03)
**目的:** バックアップデータの JSON 変換において、1ミリ秒の狂いもない完全な復元を保証する。
- **対象:** `CareMemoBackupTest.kt`

| ID       | テスト項目    | 検証内容                | 期待結果                                 |
|:---------|:---------|:--------------------|:-------------------------------------|
| UT_03_01 | 日時シリアライズ | `Instant` の JSON 変換 | ISO-8601 形式で出力され、復元後もミリ秒単位で完全に一致すること |
| UT_03_02 | 全データ構造復元 | 複雑な Entity 集合の復元    | 利用者、記録、写真情報の全フィールドが欠落なく復元されること       |

---

## 4. 非同期ライフサイクル検証 (BP-01)
**目的:** 非同期処理の競合（レースコンディション）による誤表示やデータの混在を防止する。
- **対象:** `PersonLifecycleTest.kt`

| ID       | テスト項目   | 検証内容                | 期待結果                                 |
|:---------|:--------|:--------------------|:-------------------------------------|
| BP_01_01 | 状態即時クリア | `loadPerson` 呼び出し直後 | 通信完了を待たずに ID、氏名、検索クエリ等が即座に初期化されること   |
| BP_01_02 | 競合ロード防止 | Aのロード中にBを開始         | Aの処理がキャンセル（または無視）され、最終的にBの状態が維持されること |
| BP_01_03 | 重複ロード回避 | 同じ ID での再ロード呼び出し    | 状態が変化せず、無駄なリロード（一瞬の消え）が発生しないこと       |

---

## 5. ViewModel 基盤機能検証 (BASE)
**目的:** `BaseUiStateViewModel` が提供するコルーチン制御やエラーハンドリングの共通基盤を検証する。
- **詳細仕様:** [TEST_SPEC_ViewModelFoundation.md](./viewmodel/TEST_SPEC_ViewModelFoundation.md)
- **対象:** `ViewModelFoundationTest.kt`

| ID      | テスト項目 | 検証内容             | 期待結果                                    |
|:--------|:------|:-----------------|:----------------------------------------|
| BASE_01 | 状態原子性 | 連続した状態更新         | 途中の矛盾した状態を露出せず、最終的な状態が正しく反映されること        |
| BASE_02 | 実行安全性 | `safeLaunch` の制御 | ローディング状態の自動管理、および例外発生時の監査ログ記録が確実に行われること |
