# テスト仕様書 - Logic & Data (ロジック・データ層)

- **対象テストフォルダ:**
    - `app/src/test/java/jp/mydns/fujiwara/carememo/`
    - `app/src/androidTest/java/jp/mydns/fujiwara/carememo/`

このドキュメントは、CareMemo における「目に見えない部分（ロジック、データ整合性、非同期安全性）」を担保するために実装された自動テストの仕様をまとめたものです。

## 1. ビジネスロジック・ユーティリティ (Unit Test)
**目的:** アプリ全体の計算ルールやデータ変換の正確性を検証する。

| ID    | 対象テストファイル               | 検証の目的と内容 (防いでいるリスク)                         |
|:------|:------------------------|:--------------------------------------------|
| UT-01 | `AppThresholdsTest.kt`  | 入力桁数チェック、数値フォーマッタの正確性。表示の不備防止。              |
| UT-02 | `DateTimeUtilsTest.kt`  | 和暦、年齢計算、誕生日の時刻正規化。**時刻差による別人判定バグ**の防止。      |
| UT-03 | `CareMemoBackupTest.kt` | JSONシリアライズの完全性。復元時の1ミリ秒の狂いもない完全復元。          |
| UT-04 | `*LogicTest.kt`         | 抽出されたドメインロジック（和暦変換、健康判定、保存仕分けルール等）。計算ミスの防止。 |

## 2. データ層・整合性 (Instrumented Test)
**目的:** データベース (Room/SQLite) やストレージとの整合性を検証する。

| ID    | 対象テストファイル                         | 検証の目的と内容 (防いでいるリスク)                    |
|:------|:----------------------------------|:---------------------------------------|
| DT-01 | `CareMemoDatabaseTest.kt`         | カスケード論理削除、一意制約(Upsert)。迷子データや二重登録の防止。  |
| DT-02 | `AppMaintenanceRepositoryTest.kt` | 全消去、リストア、不整合クリーンアップ。DB構造不整合による停止防止。    |
| DT-03 | `UserSettingsRepositoryTest.kt`   | DataStoreの永続化、テーマ設定の即時反映。設定の先祖返りバグ防止。  |
| DT-04 | `ImageUtilsTest.kt`               | 写真・サムネイルの物理削除、**24時間経過した一時ファイルの自動掃除**。 |

## 3. ビジネスプロセス・安全性 (Unit Test)
**目的:** ViewModel の裏側での状態管理や、各機能共通の保存ロジックを検証する。

| ID    | 対象テストファイル                      | 検証の目的と内容 (防いでいるリスク)                                                                     |
|:------|:-------------------------------|:----------------------------------------------------------------------------------------|
| BP-01 | `PersonLifecycleTest.kt`       | 利用者切り替え時の**状態即時クリア**。前利用者のデータ混在を防止。                                                     |
| BP-02 | `PersonEditViewModelTest.kt`   | **重複チェックと自己更新判定**。自分自身を編集できなくなるバグの防止。                                                   |
| BP-03 | `BatchInputViewModelTest.kt`   | **記録日時の重複チェック**。一括入力による既存データ上書きの防止。                                                     |
| BP-04 | `*RepositoryTest.kt`           | 各種操作ログ (**AuditLog**) 記録。成功時は `"SUCCESS"`、失敗時は例外型に応じ `"DB_ERROR/OTHER_ERROR"` が記録されること。 |
| BP-05 | `PersonDetailViewModelTest.kt` | データ取得失敗時の**ローディング解除**、および全情報取得までの維持。                                                    |

## 4. 実行方法
- **Unit Test**: `app/src/test` フォルダを右クリックし "Run 'Tests in...'" を実行。
- **Instrumented Test**: `app/src/androidTest` フォルダを右クリックし "Run 'Tests in...'" を実行（エミュレータまたは実機が必要）。
