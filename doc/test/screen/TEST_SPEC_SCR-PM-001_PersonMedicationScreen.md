# テスト仕様書 - SCR-PM-001 PersonMedicationScreen

- **対象テストコード:**
    - `app/src/androidTest/java/jp/mydns/fujiwara/carememo/ui/screens/medication/PersonMedicationScreenTest.kt`
    - `app/src/test/java/jp/mydns/fujiwara/carememo/viewmodel/PersonMedicationViewModelTest.kt`

## 0. 二段構え ViewModel (Dual-ViewModel) の役割
本画面は、共通フレームワークと専門ロジックを分離して管理します。

- **PersonDetailUiStateViewModel**: 利用者基本情報の保持、カテゴリ切り替え、共通UIイベントを担当。
- **PersonMedicationViewModel**: 服薬管理固有のデータ操作（CRUD）とビジネスロジックを担当。

## 1. 共通コンポーネントテスト (Header / CategoryBar)
**目的:** 全詳細画面で共通となる上部エリアの表示と基本操作を検証する。

| ID     | テスト項目         | 検証内容                                                                          |
|:-------|:--------------|:------------------------------------------------------------------------------|
| COM-01 | ヘッダー：戻るボタン    | 戻るアイコンが表示され、タップ時に `onBack` が呼ばれること。                                           |
| COM-02 | ヘッダー：利用者情報    | 利用者の氏名と年齢が正しく表示されていること。                                                       |
| COM-03 | ヘッダー：PDF出力ボタン | PDF出力アイコンが表示され、タップ時に動作すること。                                                   |
| COM-04 | カテゴリ選択バー      | タップ操作により、**利用者IDを保持したまま** `SCR-PH-001` (健康) および `SCR-PC-001` (所見) へ正しく遷移すること。 |
| COM-05 | ヘッダー：長大氏名の表示  | 氏名が非常に長い場合でも、年齢表示や各ボタンと重ならず適切に表示（省略）されること。                                    |

## 2. コンポーネント単体テスト (PersonMedicationScreenContent)
**目的:** 服薬管理固有のカレンダーや履歴表示を検証する。

| ID    | テスト項目         | 検証内容                                           |
|:------|:--------------|:-----------------------------------------------|
| CP-01 | カレンダー表示       | 当月のカレンダーが表示され、日付ごとの服薬状況（○/△/×等）が正しく反映されていること。  |
| CP-02 | 履歴テーブル表示      | 画面下部に履歴が一覧表示され、時間枠ごとの状況が確認できること。               |
| CP-03 | 未入力状態の表示      | 記録がない日を選択した際、入力ダイアログが空の状態で開くこと。                |
| CP-04 | 入力ダイアログのスクロール | 服薬の時間枠が多い場合、ダイアログ内が適切にスクロールでき、全ての項目が入力可能であること。 |

## 3. 画面全体の挙動・結合テスト (PersonMedicationScreen)
**目的:** 服薬記録の保存、削除、月切り替えなどの挙動を検証する。

| ID    | テスト項目        | 検証内容                                                                                |
|:------|:-------------|:------------------------------------------------------------------------------------|
| BH-01 | 服薬記録の保存      | ダイアログで状況を選択して保存した際、ViewModelの保存処理が呼ばれ、**親画面（SCR-M-001）へ更新を通知する状態変化を伴って**完了すること。     |
| BH-02 | 服薬記録の削除      | 既存の記録を削除した際、正しく反映され、**親画面へ更新が通知されること。**                                             |
| BH-03 | 月の切り替え       | 前月/次月ボタンの操作で、カレンダーの表示月が更新され、**該当利用者の新月のデータが正しくロードされること。**                           |
| BH-04 | PDF出力設定（服薬用） | 設定ダイアログにおいて、カレンダー範囲に基づいた期間指定ができること。また、**所見特有の「最新1件」や「写真を含める」などの無関係な項目が表示されていないこと。** |

## 4. ロジック・安全性テスト (PersonMedicationViewModel)
**目的:** 例外発生時もローディング状態が適切に解除され、画面がフリーズしないことを検証する。

| ID    | テスト項目         | 検証内容                                                                  |
|:------|:--------------|:----------------------------------------------------------------------|
| LG-01 | データロード失敗時の安全性 | 月間履歴の取得中に例外が発生した際、`uiState.isLoading` が `false` になり、エラー通知が行われること。     |
| LG-02 | 保存失敗時の安全性     | 服薬状況の更新中に例外が発生した際、`uiState.isLoading` が `false` になり、エラーダイアログが表示されること。 |
| LG-03 | 月変更と連動した原子性   | 月を切り替えた際、即座に `uiState.selectedMonth` が更新され、該当月のデータ取得が開始されること。         |

## 5. テスト用タグ (testTag) 定義
- `MedicationScreen_BackButton`: 戻るボタン
- `PersonHeader_NameAndAge`: 利用者氏名・年齢
- `MedicationScreen_PdfButton`: PDF出力ボタン
- `CategorySelectorBar`: カテゴリ選択バー
- `Medication_Calendar`: カレンダーエリア
- `Medication_HistoryTable`: 履歴テーブル
- `Medication_SaveButton`: 保存ボタン
