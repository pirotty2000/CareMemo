## 0. 二段構え ViewModel (Dual-ViewModel) の役割
本画面は、共通フレームワークと専門ロジックを分離して管理します。

- **PersonDetailUiStateViewModel**: 利用者基本情報の保持、カテゴリ切り替え、共通UIイベントを担当。
- **PersonHealthViewModel**: 健康記録固有のデータ操作（CRUD）とビジネスロジックを担当。

## 1. 共通コンポーネントテスト (Header / CategoryBar)
**目的:** 全詳細画面で共通となる上部エリアの表示と基本操作を検証する。

| ID     | テスト項目         | 検証内容                                                                                 |
|:-------|:--------------|:-------------------------------------------------------------------------------------|
| COM-01 | ヘッダー：戻るボタン    | 戻るアイコンが表示され、タップ時に `onBack` が呼ばれること。                                                  |
| COM-02 | ヘッダー：利用者情報    | 利用者の氏名と年齢が正しく表示されていること。                                                              |
| COM-03 | ヘッダー：PDF出力ボタン | PDF出力アイコンが表示され、タップ時に動作すること。                                                          |
| COM-04 | カテゴリ選択バー      | 他のカテゴリをタップした際、**選択中の利用者IDを保持したまま** `SCR-PC-001` (所見) や `SCR-PM-001` (服薬) へ正しく遷移すること。 |
| COM-05 | ヘッダー：長大氏名の表示  | 氏名が非常に長い場合でも、年齢表示や各ボタンと重ならず適切に表示（省略）されること。                                           |

## 2. コンポーネント単体テスト (PersonHealthScreenContent)
**目的:** バイタル管理固有のレイアウト表示を検証する。

| ID    | テスト項目           | 検証内容                                                                           |
|:------|:----------------|:-------------------------------------------------------------------------------|
| CP-01 | スマホ版：入力フォーム表示   | 数値入力用のフィールドと「登録」ボタンが表示されていること。                                                 |
| CP-02 | スマホ版：履歴/グラフ切り替え | スイッチ操作により、履歴リストとグラフ表示が切り替わること。                                                 |
| CP-03 | スマホ版：グラフ空状態     | 記録がない場合、グラフエリアに「データがありません」と表示されること。                                            |
| CP-04 | タブレット版：2カラム表示   | 履歴リストと詳細入力/グラフが同時に表示されていること。                                                   |
| CP-05 | タブレット版：選択連動     | 履歴リストの項目をタップした際、詳細パネル（右側）の表示内容がその項目に切り替わること。                                   |
| CP-06 | 入力カテゴリの切り替え     | 「バイタル」「血糖値」「身長体重」の切り替えにより、入力フィールドとグラフの内容が正しく更新され、入力中の未保存データがタブ切り替え後も保持されていること。 |

## 3. 画面全体の挙動・結合テスト (PersonHealthScreen)
**目的:** データの保存やグラフの拡大などの挙動を検証する。

| ID    | テスト項目        | 検証内容                                                                                   |
|:------|:-------------|:---------------------------------------------------------------------------------------|
| BH-01 | データ保存の動作     | 登録ボタンを押した際、保存処理が呼ばれ、**親画面（SCR-M-001）へ更新を通知する状態変化を伴って**完了し、監査ログに記録されること。                |
| BH-02 | グラフ拡大遷移      | グラフタップで、**利用者IDと表示期間を保持して** 拡大画面（**SCR-PH-003**）へ正しく遷移すること。                            |
| BH-03 | 日時重複時の保存ガード  | 既存データと同一日時の入力を保存しようとした際、エラーダイアログが表示され、画面が閉じないこと。                                       |
| BH-04 | PDF出力アクション   | PDF出力ボタン押下で、出力設定ダイアログが表示されること。                                                         |
| BH-05 | グラフ拡大からの戻り   | 拡大画面から戻った際、**利用者IDが不整合にならず**、元の表示状態（スクロール位置等）が維持されていること。                               |
| BH-06 | PDF出力設定（健康用） | 設定ダイアログにおいて、**期間指定（開始〜終了）が正しく行えること。** また、所見特有の「最新1件」や「写真を含める」などの**無関係な項目が表示されていないこと。** |

## 4. ロジック・安全性テスト (PersonHealthViewModel)
**目的:** 例外発生時もローディング状態が適切に解除され、画面がフリーズしないことを検証する。

| ID    | テスト項目        | 検証内容                                                                                                          |
|:------|:-------------|:--------------------------------------------------------------------------------------------------------------|
| LG-01 | データ取得失敗時の安全性 | 履歴データ取得中（Flow）中に例外が発生した際、`uiState.isLoading` が `false` になり、エラーダイアログが表示され、監査ログに `"OTHER_ERROR"` 等が記録されること。     |
| LG-02 | 保存失敗時の安全性    | データの保存中に例外が発生した際、`uiState.isLoading` が `false` になり、エラーダイアログが表示され、監査ログに記録されること。                                |
| LG-03 | バリデーション翻訳    | `PersonHealthLogic.validate` が返した「事実（Enum）」を ViewModel 内で UI 通知用の `AppValidationException` に翻訳し、監査ログに記録されること。 |
