# テスト仕様書 - SCR-M-002 PersonEditScreen

- **対象テストコード:**
    - `app/src/androidTest/java/jp/mydns/fujiwara/carememo/ui/screens/main/PersonEditScreenTest.kt`
    - `app/src/test/java/jp/mydns/fujiwara/carememo/viewmodel/PersonEditViewModelTest.kt`

## 1. コンポーネント単体テスト (PersonEditScreenContent)
**目的:** 入力項目の表示、バリデーションによる保存ボタンの活性・非活性状態、初期値の反映などを検証する。

| ID    | テスト項目        | 検証内容                                                |
|:------|:-------------|:----------------------------------------------------|
| CP-01 | 初期表示（新規）     | 全ての入力フィールドが空（またはデフォルト値）で表示されること。                    |
| CP-02 | 初期表示（編集）     | **親画面から渡された利用者IDに基づき**、該当するデータが各フィールドに正しく反映されていること。 |
| CP-03 | 未入力バリデーション   | 「姓」「名」「年」「月」「日」のいずれかが空の場合、保存ボタンが非活性であること。           |
| CP-04 | 必須項目の入力完了    | 「姓」「名」「年」「月」「日」の全てが入力された時、保存ボタンが活性化すること。            |
| CP-05 | 任意項目の入力      | 「せい」「めい」「識別メモ」が空であっても、必須項目が埋まっていれば保存可能であること。        |
| CP-06 | カレンダー選択の切り替え | 和暦・西暦のセレクタを切り替えた際、年入力の表示が正しく更新されること。                |
| CP-07 | 長大文字列の表示     | 姓名や識別メモに非常に長い文字列が入力された際、レイアウトが崩れないこと。               |

## 2. 画面全体の挙動・結合テスト (PersonEditScreen)
**目的:** データの重複チェックロジックや、新規・更新の適切な使い分けを検証する。

| ID    | テスト項目         | 検証内容                                                        |
|:------|:--------------|:------------------------------------------------------------|
| BH-01 | 重複データの警告表示    | 既存の別利用者と「姓・名・生年月日・識別メモ」が一致する際、重複警告が表示されること。                 |
| BH-02 | 同姓同名・同年月日の許容  | 「姓・名・生年月日」が一致していても、「識別メモ」が異なれば重複とみなされないこと。                  |
| BH-03 | 編集モードでの更新処理   | 編集モードにおいて保存した際、新規追加(Insert)ではなく既存レコードの更新(Update)が行われること。    |
| BH-04 | 重複警告からのメモ編集   | 重複警告ダイアログで「編集を続ける」を選択した際、識別メモへフォーカスが移動すること。                 |
| BH-05 | キャンセル動作       | キャンセルボタンまたは戻る操作で、確認ダイアログが表示されること。                           |
| BH-06 | 不正な日付のバリデーション | 「2月31日」など存在しない日付が指定された場合、保存ボタンが非活性になること。                    |
| BH-07 | 保存成功と画面終了     | 保存が正常に完了した際、**呼び出し元に更新を促すシグナル（またはDBの更新通知）を伴って**画面が閉じ、戻ること。  |
| BH-08 | 保存失敗時の挙動      | 保存中にエラー（DBエラー等）が発生した際、エラーダイアログが表示され、入力中のデータが維持されること。        |
| BH-09 | バリデーションエラー表示  | 保存実行時、入力不備（姓名未入力、不正な日付等）がある場合に、具体的な不備内容を示すエラーダイアログが表示されること。 |

## 3. ロジック・安全性テスト (PersonEditViewModel)
**目的:** 例外発生時もローディング状態が適切に解除され、画面がフリーズしないことを検証する。

| ID    | テスト項目          | 検証内容                                                                            |
|:------|:---------------|:--------------------------------------------------------------------------------|
| LG-01 | データ読み込み失敗時の安全性 | 既存データのロード中に例外が発生した際、`uiState.isLoading` が `false` になり、監査ログに記録されること。             |
| LG-02 | 保存失敗時の安全性      | 保存中に例外が発生した際、`uiState.isLoading` が `false` になり、監査ログに記録されること。                    |
| LG-03 | バリデーション結果の翻訳   | `PersonEditLogic.validate` の結果（事実）が、適切な `AppValidationException`（UI通知）に翻訳されること。 |

## 4. テスト用タグ (testTag) 定義
- `PersonEdit_LastName`: 姓入力フィールド
- `PersonEdit_FirstName`: 名入力フィールド
- `PersonEdit_LastNameKana`: せい入力フィールド
- `PersonEdit_FirstNameKana`: めい入力フィールド
- `PersonEdit_Memo`: 同姓同名識別メモ入力フィールド
- `PersonEdit_EraSelector`: 和暦・西暦セレクタ
- `PersonEdit_BirthYear`: 年入力フィールド
- `PersonEdit_BirthMonth`: 月入力フィールド
- `PersonEdit_BirthDay`: 日入力フィールド
- `PersonEdit_SaveButton`: 保存ボタン
- `PersonEdit_CancelButton`: キャンセルボタン
- `PersonEdit_DuplicateDialog`: 重複警告ダイアログ
