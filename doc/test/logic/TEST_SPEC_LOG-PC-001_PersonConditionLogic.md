# テスト仕様書 - LOG-PC-001 PersonConditionLogic

- **対象テストコード:**
    - `app/src/test/java/jp/mydns/fujiwara/carememo/logic/feature/PersonConditionLogicTest.kt`

## 0. UI 状態の構造 (PersonConditionUiState)
**集約されたプロパティ:**
- 入力フィールド: `title`, `condition`, `author`, `recordTime`
- 利用者コンテキスト: `personId`
- 画面固有の状態: `records`, `filteredRecords`, `searchQuery`, `selectedConditionId`, `currentConditionPhotos`, `conditionPhotoMap`
- 派生・制御状態: `isLoading`, `isProcessing`, `errorMessage`

## 1. 変更検知テスト (isChanged)
**目的:** 画面上の入力内容が初期状態から変更されたかを正しく判定できることを検証する。

| ID     | テスト項目      | 条件 (入力)                           | 期待結果 (戻り値) |
|:-------|:-----------|:----------------------------------|:----------:|
| CHG-01 | 変更なし（初期状態） | 全てのフィールドが初期データと一致                 |  `false`   |
| CHG-02 | タイトルの変更    | タイトルのみ異なる内容を入力                    |   `true`   |
| CHG-03 | 内容の変更      | 所見内容のみ異なる内容を入力                    |   `true`   |
| CHG-04 | 記録者の変更     | 記録者のみ異なる内容を入力                     |   `true`   |
| CHG-05 | 記録日時の変更    | 記録日時のみ異なる日時を選択                    |   `true`   |
| CHG-06 | 新規作成（未入力）  | 初期データなし、UiState がデフォルト値、記録者がデフォルト |  `false`   |
| CHG-07 | 新規作成（入力あり） | 初期データなし、何らかの項目を入力済み               |   `true`   |

## 2. バリデーションテスト (validate)
**目的:** 入力内容の妥当性をビジネスルールに則って判定し、適切な「事実」を返せることを検証する。

| ID     | テスト項目   | 条件 (入力)            | 期待結果 (Enum)          |
|:-------|:--------|:-------------------|:---------------------|
| VAL-01 | 正常な入力   | 全ての必須項目が適切に入力されている | `SUCCESS`            |
| VAL-02 | 内容が空    | 所見内容が空文字または空白のみ    | `EMPTY_CONDITION`    |
| VAL-03 | 記録者が空   | 記録者が空文字または空白のみ     | `EMPTY_AUTHOR`       |
| VAL-04 | 日時が未指定  | 記録日時が `null`       | `INVALID_TIME`       |
| VAL-05 | 文字数制限超過 | 所見内容が1001文字以上      | `CONDITION_TOO_LONG` |

## 3. Entity 生成テスト (createRecord)
**目的:** UI状態からデータベース保存用の Entity が正しく構築されることを検証する。

| ID     | テスト項目      | 検証内容                                                        |
|:-------|:-----------|:------------------------------------------------------------|
| CRT-01 | プロパティの詰め替え | 各フィールド（タイトル、内容、記録者、日時）が Entity の対応するプロパティに正しくセットされること。      |
| CRT-02 | 空白のトリミング   | タイトル、内容、記録者の前後にある空白が `trim()` されて保存用データになること。               |
| CRT-03 | 不正データでの例外  | 日時が `null` の状態で呼び出した際、`IllegalArgumentException` がスローされること。 |

## 4. 補助機能テスト (isValid)
**目的:** UI上での保存ボタン活性・非活性制御用の判定が正しいことを検証する。

| ID     | テスト項目  | 検証内容                                       |
|:-------|:-------|:-------------------------------------------|
| VLD-01 | 保存可能判定 | `validate` が `SUCCESS` のときのみ `true` を返すこと。 |
