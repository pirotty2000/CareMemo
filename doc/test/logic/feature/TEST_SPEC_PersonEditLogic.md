# テスト仕様書 - PersonEditLogic

- **対象テストコード:**
    - `app/src/test/java/jp/mydns/fujiwara/carememo/logic/feature/PersonEditLogicTest.kt`

## 1. 概要
利用者の基本情報（氏名、ふりがな、生年月日、備考）の登録・編集に関するドメインロジックの正確性を検証する。
特に入力値の変更検知、ビジネスルールに基づくバリデーション、および UI 状態から Entity への正規化を伴う変換を対象とする。

## 2. 変更検知テスト (isChanged)
**目的:** 利用者の情報が初期状態（または DB の元の値）から変更されたかを正しく判定できることを検証する。

| ID     | テスト項目    | 条件 (入力状況)               |  期待結果   |
|:-------|:---------|:------------------------|:-------:|
| CHG-01 | 変更なし（新規） | 全てのフィールドが空・デフォルト値       | `false` |
| CHG-02 | 入力あり（新規） | いずれかのフィールド（氏名、年など）に入力あり | `true`  |
| CHG-03 | 変更なし（更新） | 全てのフィールドが初期 Entity と一致  | `false` |
| CHG-04 | 氏名の変更    | 姓または名の一方のみを変更           | `true`  |
| CHG-05 | 生年月日の変更  | 元号、年、月、日のいずれかを変更        | `true`  |
| CHG-06 | 備考の変更    | 備考欄を変更                  | `true`  |

## 3. バリデーションテスト (validate / isValid)
**目的:** 入力内容の妥当性を判定し、適切な「事実」および保存可否（isValid）を返せることを検証する。

| ID     | テスト項目    | 条件 (入力)            | 期待結果 (Enum)            | isValid |
|:-------|:---------|:-------------------|:-----------------------|:-------:|
| VAL-01 | 正常な入力    | 全ての必須項目が適切に入力されている | `SUCCESS`              | `true`  |
| VAL-02 | 姓が空      | 苗字が未入力または空白のみ      | `EMPTY_LAST_NAME`      | `false` |
| VAL-03 | 名が空      | 名前が未入力または空白のみ      | `EMPTY_FIRST_NAME`     | `false` |
| VAL-04 | ふりがな(姓)空 | ふりがな(姓)が未入力        | `EMPTY_LAST_FURIGANA`  | `false` |
| VAL-05 | ふりがな(名)空 | ふりがな(名)が未入力        | `EMPTY_FIRST_FURIGANA` | `false` |
| VAL-06 | 生年月日不正   | 存在しない日付（例：2月30日）   | `INVALID_BIRTHDAY`     | `false` |
| VAL-07 | 氏名文字数超過  | 姓または名が制限文字数（50文字）超 | `NAME_TOO_LONG`        | `false` |
| VAL-08 | 備考文字数超過  | 備考が制限文字数（200文字）超   | `NOTE_TOO_LONG`        | `false` |

## 4. Entity 生成テスト (createPerson)
**目的:** UI状態からデータベース保存用の Entity が正しく構築・正規化されることを検証する。

| ID     | テスト項目      | 検証内容                                   | 期待結果                       |
|:-------|:-----------|:---------------------------------------|:---------------------------|
| CRT-01 | プロパティの詰め替え | 各フィールドが Entity に正しくセットされること            | 一致すること                     |
| CRT-02 | 空白のトリミング   | 氏名、ふりがな、備考の前後にある空白が除去されること             | `trim()` 済みであること           |
| CRT-03 | IDの維持      | 更新時（initial != null）に元の ID が維持されること    | ID が一致すること                 |
| CRT-04 | 新規IDの発行    | 新規時（initial == null）に新しい UUID が設定されること | 有効な UUID であること             |
| CRT-05 | 不正データでの例外  | 日付変換不能な状態で呼び出し                         | `IllegalArgumentException` |
