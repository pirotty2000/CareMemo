# テスト仕様書 - PersonListLogic

- **対象テストコード:**
    - `app/src/test/java/jp/mydns/fujiwara/carememo/logic/feature/PersonListLogicTest.kt`

## 1. 概要
利用者一覧画面（MainScreen）における表示データの加工ロジックを検証する。
特に五十音行の判定、リストのフィルタリング、UI表示用データへの変換、および重複判定の正確性を対象とする。

## 2. 五十音行判定テスト (getSection)
**目的:** 利用者のふりがな（姓）から、正しい五十音インデックス（あ、か、さ...）が導き出されることを検証する。

| ID     | テスト項目      | 条件 (入力：ふりがなの先頭文字) |  期待結果  |
|:-------|:-----------|:------------------|:------:|
| SEC-01 | あ行の判定      | 「あ」「い」「う」「え」「お」   |  「あ」   |
| SEC-02 | か行の判定      | 「か」「き」「く」「け」「こ」   |  「か」   |
| SEC-03 | 濁音・半濁音の判定  | 「が」「ざ」「だ」「ば」「ぱ」   | 各行の頭文字 |
| SEC-04 | 促音・拗音の判定   | 「っ」「ゃ」            | 各行の頭文字 |
| SEC-05 | わ行・んの判定    | 「わ」「を」「ん」         |  「わ」   |
| SEC-06 | 記号・英数字・空文字 | 「A」「1」「-」「」       |  「他」   |

## 3. リストフィルタリングテスト (filterPersons)
**目的:** 選択された五十音行や、キーワード検索の結果に基づき、正しくフィルタリングされることを検証する。

| ID     | テスト項目   | 条件 (入力)                             | 期待結果                  |
|:-------|:--------|:------------------------------------|:----------------------|
| FLT-01 | 全表示     | section="全", matchedIds=null        | 全てのデータが含まれること         |
| FLT-02 | 五十音フィルタ | section="か"                         | 苗字が「か行」の人（濁音含む）のみ抽出   |
| FLT-03 | 検索フィルタ  | matchedIds=["1", "3"]               | 指定された ID の人のみ抽出       |
| FLT-04 | 複合フィルタ  | section="あ", matchedIds=["1", "10"] | 「あ行」かつ IDが"1", "10"の人 |
| FLT-05 | 該当なし    | 条件に合う人がいない                          | 空リストを返すこと             |

## 4. UI状態変換テスト (createPersonUiState)
**目的:** エンティティから UI 表示用のデータクラスへ、正確に情報が加工・変換されることを検証する。

| ID    | テスト項目    | 検証内容                        | 期待結果                     |
|:------|:---------|:----------------------------|:-------------------------|
| UI-01 | 伏せ字の適用   | `isMasking=true`            | 氏名とふりがなが適切にマスクされること      |
| UI-02 | 年齢計算     | `birthday` からの算出            | 現在の年齢が正しく計算されること         |
| UI-03 | 和暦フォーマット | `birthday` からの変換            | 「昭和XX年XX月XX日」等の形式であること   |
| UI-04 | サマリーの結合  | `PersonCategorySummary` の反映 | 記録有無の状態が正しく保持されること       |
| UI-05 | サマリーなし   | `summary=null` での呼び出し       | 全て `false` の初期状態で生成されること |

## 5. 重複判定テスト (validateDuplicate)
**目的:** 利用者の追加・更新時に、既存データとの重複（氏名・生年月日・備考の一致）を正しく判定できることを検証する。

| ID     | テスト項目    | 条件 (入力データ)           | 期待結果 (Enum)          |
|:-------|:---------|:---------------------|:---------------------|
| DUP-01 | 重複なし     | 全く一致する人が存在しない        | `SUCCESS`            |
| DUP-02 | 重複あり（有効） | 一致する人が「有効」状態で存在      | `DUPLICATE_ACTIVE`   |
| DUP-03 | 重複あり（終了） | 一致する人が「利用終了」状態で存在    | `DUPLICATE_ARCHIVED` |
| DUP-04 | 自分自身との一致 | IDが一致する既存データが見つかった場合 | `SUCCESS`            |
