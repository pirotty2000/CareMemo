# テスト仕様書 - PersonHealthLogic

- **対象テストコード:**
    - `app/src/test/java/jp/mydns/fujiwara/carememo/logic/feature/PersonHealthLogicTest.kt`
- **関連するロジック仕様書:**
    - [HealthLogic (共通計算ルール)](../common/TEST_SPEC_HealthLogic.md)

## 1. 概要
健康記録画面（カテゴリA, C, D）における、バリデーション判定および Entity 構築のドメインロジックの正確性を検証する。
本ロジックは内部で `HealthCategoryProcessor` を介して各カテゴリ固有の処理を実行するため、ここでは画面全体としての判定の一貫性を検証する。

## 2. 数値妥当性テスト (validate)
**目的:** 各記録型（身長体重、バイタル、血糖）に応じた数値範囲の妥当性が正しく判定されることを検証する。

| ID     | テスト項目      | 条件 (入力データ)        | 期待結果                |
|:-------|:-----------|:------------------|:--------------------|
| VAL-01 | 正常な値（身長体重） | 範囲内の身長・体重         | `SUCCESS`           |
| VAL-02 | 異常な値（身長）   | 規定範囲外の数値          | `INVALID_VALUE`     |
| VAL-03 | 正常な値（バイタル） | 範囲内の血圧・脈拍・SAT・体温  | `SUCCESS`           |
| VAL-04 | 正常な値（血糖値）  | 範囲内の血糖値・HbA1c     | `SUCCESS`           |
| VAL-05 | null入力     | null（未入力）を含む各レコード | `SUCCESS` (nullは許容) |

## 3. 重複判定テスト (validateDuplicate)
**目的:** 既存データとの時間重複を正しく判定し、自分自身を除外できることを検証する。

| ID     | テスト項目    | 条件 (入力データ)                 | 期待結果 (事実)        |
|:-------|:---------|:---------------------------|:-----------------|
| DUP-01 | 重複なし（新規） | 既存データなし (null)             | `SUCCESS`        |
| DUP-02 | 重複あり（新規） | 同じ時間の別レコードが既に存在            | `DUPLICATE_TIME` |
| DUP-03 | 重複なし（更新） | 同じ時間のレコードが存在するが、自分自身(ID一致) | `SUCCESS`        |
| DUP-04 | 重複あり（更新） | 同じ時間のレコードが存在し、自分以外(ID不一致)  | `DUPLICATE_TIME` |

## 4. UI入力一括評価テスト (validateInputs)
**目的:** UI層からの文字列入力マップが、カテゴリごとに正しくバリデーションされることを検証する。

| ID    | テスト項目 | 条件 (入力)     |       期待結果       |
|:------|:------|:------------|:----------------:|
| UI-01 | 身長体重  | 有効な文字列マップ   |    `SUCCESS`     |
| UI-02 | バイタル  | 一部未入力を含むマップ |    `SUCCESS`     |
| UI-03 | 形式不正  | 数値以外の文字を含む  | `INVALID_FORMAT` |

## 5. Entity 生成テスト (createEntity)
**目的:** 入力内容から永続化用 Entity が正しく構築・正規化されることを検証する。

| ID     | テスト項目      | 検証内容                         | 期待結果                       |
|:-------|:-----------|:-----------------------------|:---------------------------|
| CRT-01 | プロパティの詰め替え | 各フィールドが Entity に正しくセットされること  | 一致すること                     |
| CRT-02 | 新規IDの発行    | ID が新規用の場合、新しい UUID が発行されること | 有効な UUID であること             |
| CRT-03 | 既存IDの維持    | ID が指定されている場合、その ID が維持されること | 指定した ID と一致すること            |
| CRT-04 | 未サポートカテゴリ  | 想定外のカテゴリを指定                  | `IllegalArgumentException` |

## 6. 安全な型変換テスト (Safe Type Conversion)
**目的:** `Map<String, Any?>` から値を抽出する際、入力された数値型（Int, Double）に関わらず、期待する型（Double, Int）へ安全に変換・抽出できることを検証する。

| ID     | テスト項目         | 条件 (入力)                      | 期待結果 (戻り値)      |
|:-------|:---------------|:-------------------------------|:-----------------|
| SAF-01 | getDouble: 整数   | `100` (Int)                    | `100.0` (Double) |
| SAF-02 | getDouble: 小数   | `100.5` (Double)               | `100.5` (Double) |
| SAF-03 | getDouble: 非数値  | `"abc"` (String)               | `null`           |
| SAF-04 | getInt: 整数      | `120` (Int)                    | `120` (Int)      |
| SAF-05 | getInt: 小数(参考) | `36.5` (Double)                | `36` (Int)       |
| SAF-06 | getInt: 非数値     | `null`                         | `null`           |
