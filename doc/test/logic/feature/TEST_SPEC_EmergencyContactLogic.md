# テスト仕様書 - EmergencyContactLogic

- **対象テストコード:**
    - `app/src/test/java/jp/mydns/fujiwara/carememo/logic/feature/EmergencyContactLogicTest.kt`

## 1. 概要
緊急連絡先管理（MedicalContact）に関連するドメインロジックの正確性を検証する。
特に、入力内容の妥当性検証、保存データの正規化（クレンジング）、および初期データの生成ロジックを対象とする。

## 2. バリデーションテスト (validate / isValid)
**目的:** 入力内容がビジネスルール（必須チェック、文字数制限）に適合しているかを検証する。

| ID    | テスト項目      | 条件 (入力データ)        | 期待結果 (事実)                |
|:------|:-----------|:------------------|:-------------------------|
| VL-01 | 正常系：最小構成   | 施設名のみ入力           | `SUCCESS`                |
| VL-02 | 正常系：全項目入力  | 施設名、担当者、電話番号を全て入力 | `SUCCESS`                |
| VL-03 | 異常系：施設名空   | 施設名が未入力または空白のみ    | `EMPTY_FACILITY_NAME`    |
| VL-04 | 異常系：施設名長大  | 施設名が規定文字数超過       | `FACILITY_NAME_TOO_LONG` |
| VL-05 | 異常系：担当者名長大 | 担当者名が規定文字数超過      | `PERSON_NAME_TOO_LONG`   |
| VL-06 | 異常系：電話番号長大 | 電話番号が規定文字数超過      | `PHONE_NUMBER_TOO_LONG`  |

## 3. データ正規化テスト (createSaveEntity)
**目的:** 保存直前に、不要な空白の除去や電話番号の記号除去が正しく行われることを検証する。

| ID    | テスト項目        | 条件 (入力)          | 期待結果 (正規化後)      |
|:------|:-------------|:-----------------|:-----------------|
| NM-01 | 空白のトリミング     | 施設名・担当者名の前後に空白あり | 空白が除去されていること     |
| NM-02 | 電話番号の正規化     | ハイフン等の記号を含む電話番号  | 数字のみが抽出されていること   |
| NM-03 | 空白項目の null 化 | 空白のみ入力された任意項目    | `null` として扱われること |

## 4. 状態判定テスト (isChanged)
**目的:** 編集前後での Entity の変更有無を正しく判定できることを検証する。

| ID    | テスト項目   | 条件 (比較内容)                |  期待結果   |
|:------|:--------|:-------------------------|:-------:|
| ST-01 | 変更なし    | 全く同じプロパティを持つ 2 つの Entity | `false` |
| ST-02 | 基本項目の変更 | 施設名が異なる                  | `true`  |
| ST-03 | 優先度の変更  | 優先度 (priority) のみが異なる    | `true`  |

## 5. 初期データ生成テスト (createInitialEntity)
**目的:** 新規登録用の初期エンティティが、正しいデフォルト値で生成されることを検証する。

| ID     | テスト項目  | 検証内容               | 期待結果                            |
|:-------|:-------|:-------------------|:--------------------------------|
| INI-01 | デフォルト値 | `personId` を指定して生成 | IDが新規用、種別がDOCTOR、優先度がデフォルトであること |
