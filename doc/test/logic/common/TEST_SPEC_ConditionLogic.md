# テスト仕様書 - ConditionLogic

- **対象テストコード:**
    - `app/src/test/java/jp/mydns/fujiwara/carememo/logic/common/ConditionLogicTest.kt`

## 1. 概要
所見メモ（カテゴリB）におけるドメイン共通ロジックの正確性を検証する。
主に検索フィルタリングと、保存時の日時重複チェックのルールを対象とする。

## 2. 検索フィルタリングテスト (filterRecords)
**目的:** 検索クエリに基づき、リストから適切なレコードが抽出されることを検証する。

| ID     | テスト項目     | 条件 (入力)              | 期待結果 (リスト内容)   |
|:-------|:----------|:---------------------|:---------------|
| FLT-01 | フィルタなし    | クエリ = ""             | 全てのレコードが返されること |
| FLT-02 | タイトル一致    | タイトルに含まれる文字列         | 一致するレコードのみ抽出   |
| FLT-03 | 本文一致      | 本文に含まれる文字列           | 一致するレコードのみ抽出   |
| FLT-04 | 大文字小文字の区別 | "TEST" (ソースが "test") | 区別せず抽出されること    |
| FLT-05 | 該当なし      | 存在しない文字列             | 空リストが返されること    |

## 3. 重複判定テスト (validateDuplicate)
**目的:** 保存しようとしているデータが、既存のデータと時間の重複（同一利用者、同一時間）を起こしていないかを判定する。

| ID     | テスト項目    | 条件 (入力)                    | 期待結果 (Enum)      |
|:-------|:---------|:---------------------------|:-----------------|
| DUP-01 | 重複なし（新規） | 既存データなし (null)             | `SUCCESS`        |
| DUP-02 | 重複あり（新規） | 同じ時間の別レコードが既に存在            | `DUPLICATE_TIME` |
| DUP-03 | 重複なし（更新） | 同じ時間のレコードが存在するが、自分自身(ID一致) | `SUCCESS`        |
| DUP-04 | 重複あり（更新） | 同じ時間のレコードが存在し、自分以外(ID不一致)  | `DUPLICATE_TIME` |
