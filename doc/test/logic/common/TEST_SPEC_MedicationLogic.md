# テスト仕様書 - MedicationLogic

- **対象テストコード:**
    - `app/src/test/java/jp/mydns/fujiwara/carememo/logic/common/MedicationLogicTest.kt`

## 1. カレンダー生成テスト (getCalendarDays)
**目的:** 指定された年月に基づき、カレンダー表示用の日付リスト（日曜開始のグリッド調整用空セルを含む）が正しく生成されることを検証する。

| ID     | テスト項目   | 条件 (入力)        | 期待結果                                  |
|:-------|:--------|:---------------|:--------------------------------------|
| CAL-01 | 月初が日曜以外 | 2023-11 (水曜開始) | リスト長 33, インデックス 0-2 が null, 3 が 11/1  |
| CAL-02 | 閏年の2月   | 2024-02 (木曜開始) | リスト長 33, インデックス 0-3 が null, 32 が 2/29 |
| CAL-03 | 月初が日曜   | 2023-10 (日曜開始) | リスト長 31, インデックス 0 が 10/1              |

## 2. 同期アクション判定テスト (determineSyncActions)
**目的:** データベース上の現在の記録と、画面からの入力状態を比較し、適切な DB 操作（追加・更新・削除・維持）が導き出されることを検証する。

| ID     | テスト項目   | 条件 (入力：既存, 入力)       | 期待結果 (SyncAction) |
|:-------|:--------|:---------------------|:------------------|
| SYN-01 | 新規追加    | 既存=[], 入力=[朝:服用]     | `Insert(朝:服用)`    |
| SYN-02 | ステータス更新 | 既存=[朝:服用], 入力=[朝:介助] | `Insert(朝:介助)`    |
| SYN-03 | 削除      | 既存=[朝:服用], 入力=[null] | `Delete(朝:服用)`    |
| SYN-04 | 変更なし    | 既存=[朝:服用], 入力=[朝:服用] | `None`            |

## 3. バリデーションテスト (validateMedication)
**目的:** 服薬記録の内容が業務ルールに適合しているかを判定し、事実を返せることを検証する。

| ID     | テスト項目   | 条件 (入力)            | 期待結果 (Enum)               |
|:-------|:--------|:-------------------|:--------------------------|
| VAL-01 | 正常な入力   | 全ての項目が範囲内          | `SUCCESS`                 |
| VAL-02 | 未来日付の制限 | 本日より後の日付を指定        | `FUTURE_DATE_NOT_ALLOWED` |
| VAL-03 | 不正ステータス | ステータスコードが 0,1,2 以外 | `INVALID_STATUS`          |

## 4. データクレンジングテスト (filterValidRecords)
**目的:** 不正なステータスを持つレコードがリストから正しく除外されることを検証する。

| ID     | テスト項目  | 条件 (入力)       | 期待結果                   |
|:-------|:-------|:--------------|:-----------------------|
| CLN-01 | 正常なリスト | 全てステータス 0-2   | 全件残ること                 |
| CLN-02 | 不正混入   | ステータス 9 が含まれる | ステータス 9 のレコードのみ除外されること |
