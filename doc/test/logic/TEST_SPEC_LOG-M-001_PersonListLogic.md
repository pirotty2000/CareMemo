# テスト仕様書 - LOG-M-001 PersonListLogic

- **対象テストコード:**
    - `app/src/test/java/jp/mydns/fujiwara/carememo/logic/feature/PersonListLogicTest.kt`

## 1. 五十音行判定テスト (getSection)
**目的:** 利用者のふりがな（姓）から、正しい五十音インデックス（あ、か、さ...）が導き出されることを検証する。

| ID     | テスト項目       | 条件 (入力：ふりがなの先頭文字) | 期待結果 (戻り値) |
|:-------|:------------|:------------------|:----------:|
| SEC-01 | あ行の判定       | 「あ」「い」「う」「え」「お」   |    「あ」     |
| SEC-02 | か行の判定       | 「か」「き」「く」「け」「こ」   |    「か」     |
| SEC-03 | か行（濁音）の判定   | 「が」「ぎ」「ぐ」「げ」「ご」   |    「か」     |
| SEC-04 | さ行（濁音含む）の判定 | 「さ」「ざ」            |    「さ」     |
| SEC-05 | た行（濁音含む）の判定 | 「た」「だ」            |    「た」     |
| SEC-06 | た行（促音）の判定   | 「っ」 (例: っしま)      |    「た」     |
| SEC-07 | は行（濁音・半濁音）  | 「は」「ば」「ぱ」         |    「は」     |
| SEC-08 | わ行・んの判定     | 「わ」「を」「ん」         |    「わ」     |
| SEC-09 | 記号・英数字・空文字  | 「A」「1」「-」「」       |    「他」     |

## 2. リストフィルタリングテスト (filterPersons)
**目的:** 選択された五十音行や、検索キーワードに一致したIDリストに基づき、正しくフィルタリングされることを検証する。

| ID     | テスト項目   | 条件 (入力)                         | 期待結果 (リスト内容)         |
|:-------|:--------|:--------------------------------|:---------------------|
| FLT-01 | 全表示     | section="全", matchedIds=null    | 全てのデータが含まれること        |
| FLT-02 | 五十音フィルタ | section="か"                     | 苗字が「か行」の人のみ含まれること    |
| FLT-03 | 検索フィルタ  | matchedIds=[1, 3] (検索結果)        | IDが 1 と 3 の人のみ含まれること |
| FLT-04 | 複合フィルタ  | section="あ", matchedIds=[1, 10] | 「あ行」かつ IDが1, 10の人    |
| FLT-05 | 該当なし    | 条件に合う人がいない                      | 空リストを返すこと            |

## 3. UI状態変換テスト (createPersonUiState)
**目的:** エンティティから UI 表示用のデータクラスへ、正確に情報が加工・変換されることを検証する。

| ID    | テスト項目      | 検証内容                                              |
|:------|:-----------|:--------------------------------------------------|
| UI-01 | 伏せ字の適用     | `isMasking=true` のとき、氏名とふりがなが伏せ字化されること。           |
| UI-02 | 年齢計算       | 生年月日から現在の年齢が正しく計算されること。                           |
| UI-03 | 和暦フォーマット   | 生年月日が「昭和XX年XX月XX日」のような和暦形式でフォーマットされること。           |
| UI-04 | サマリーの結合    | 記録有無のサマリー（`PersonCategorySummary`）が正しくセットされること。   |
| UI-05 | サマリーなし（新規） | サマリーが `null` で渡された場合、全て `false` のデフォルト値がセットされること。 |

## 4. 重複判定テスト (validateDuplicate) ※新規追加
**目的:** 追加・更新時に既存データとの重複（氏名・生年月日の一致）を「事実」として判定できることを検証する。

| ID     | テスト項目    | 条件 (入力)                       | 期待結果 (Enum)          |
|:-------|:---------|:------------------------------|:---------------------|
| DUP-01 | 重複なし     | 姓名・生年月日が一致する人が存在しない           | `SUCCESS`            |
| DUP-02 | 重複あり（有効） | 姓名・生年月日が一致する人が「有効」状態で存在       | `DUPLICATE_ACTIVE`   |
| DUP-03 | 重複あり（終了） | 姓名・生年月日が一致する人が「利用終了（論理削除）」で存在 | `DUPLICATE_ARCHIVED` |
| DUP-04 | 自分自身との一致 | IDが一致する既存データが見つかった場合（更新時）     | `SUCCESS`            |
