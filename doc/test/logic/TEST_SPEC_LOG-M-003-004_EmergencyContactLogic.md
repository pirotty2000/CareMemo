# テスト仕様書 - EmergencyContactLogic

- **対象テストコード:** `app/src/test/java/jp/mydns/fujiwara/carememo/logic/common/EmergencyContactLogicTest.kt`

## 1. バリデーションテスト (validate / isValid)
**目的:** 入力内容がビジネスルール（必須・文字数）に適合しているかを検証する。

| ID    | テスト項目      | 入力値（Entity 状態）                          | 期待結果 (ValidationResult) |
|:------|:-----------|:----------------------------------------|:------------------------|
| VL-01 | 正常系：最小構成   | 施設名: "A病院", 他: null                     | SUCCESS                 |
| VL-02 | 正常系：全項目入力  | 施設名: "A病院", 担当: "B先生", 電話: "0312345678" | SUCCESS                 |
| VL-03 | 異常系：施設名空   | 施設名: "" (空文字)                           | EMPTY_FACILITY_NAME     |
| VL-04 | 異常系：施設名長大  | 施設名: "101文字以上の文字列..."                   | FACILITY_NAME_TOO_LONG  |
| VL-05 | 異常系：担当者名長大 | 担当者名: "101文字以上の文字列..."                  | PERSON_NAME_TOO_LONG    |
| VL-06 | 異常系：電話番号長大 | 電話番号: "16文字以上の数字..."                    | PHONE_NUMBER_TOO_LONG   |

## 2. データ正規化テスト (createSaveEntity)
**目的:** 保存直前に、不要な空白や記号が適切に除去されることを検証する。

| ID    | テスト項目        | 入力値                                | 期待結果 (正規化後の値)                 |
|:------|:-------------|:-----------------------------------|:------------------------------|
| NM-01 | 空白のトリミング     | 施設名: "  〇〇クリニック  ", 担当: "  田中先生  " | "〇〇クリニック", "田中先生"             |
| NM-02 | 電話番号の記号除去    | 電話番号: "090-1234-5678"              | "09012345678"                 |
| NM-03 | 電話番号の非数字混入   | 電話番号: "03(1234)5678 ext123"        | "0312345678123"               |
| NM-04 | 空白項目の null 化 | 担当者名: "   " (空白のみ), 電話番号: "" (空文字) | personName: null, phone: null |

## 3. 状態判定テスト (isChanged)
**目的:** 編集前後の Entity 比較が正しく行われることを検証する。

| ID    | テスト項目   | 比較内容                             | 期待結果  |
|:------|:--------|:---------------------------------|:------|
| ST-01 | 変更なし    | 全く同じプロパティを持つ 2 つの Entity を比較     | false |
| ST-02 | 基本項目の変更 | 施設名のみ異なる Entity を比較              | true  |
| ST-03 | 優先度の変更  | 優先度 (priority) のみが異なる Entity を比較 | true  |
