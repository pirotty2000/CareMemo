# テスト仕様書 - AuditLogRepository

- **対象テストコード:**
    - `app/src/test/java/jp/mydns/fujiwara/carememo/data/repository/AuditLogRepositoryTest.kt`

## 1. 概要
操作ログ（監査ログ）の保存、取得、および保持期間に基づいた自動削除ロジックの正確性を検証する。
特に、ログ記録時の例外が業務処理を妨げない設計（堅牢性）と、期間計算の妥当性を対象とする。

## 2. ログ記録テスト (log)
**目的:** 操作ログが正しく DAO に渡されること、およびエラー発生時も呼び出し側に影響を与えないことを検証する。

| ID     | テスト項目      | 検証内容                  | 期待結果                                                |
|:-------|:-----------|:----------------------|:----------------------------------------------------|
| LOG-01 | 正常な記録      | 有効な引数で `log` を実行      | 期待される値を持つ `AuditLog` エンティティが DAO の `insert` に渡されること |
| LOG-02 | 例外の隠蔽と緊急ログ | DAO の `insert` で例外が発生 | 呼び出し側に例外が伝播されず、`SystemEmergencyLogger` への出力が試みられること |

## 3. ログ削除・ローテーションテスト (Delete)
**目的:** 指定された条件に従ってログが物理削除されることを検証する。

| ID     | テスト項目  | 条件 (入力)                  | 期待結果                                                    |
|:-------|:-------|:-------------------------|:--------------------------------------------------------|
| DEL-01 | 期間指定削除 | `retentionDays = 30` を指定 | 現在時刻から 30 日前の `Instant` が DAO の `deleteOldLogs` に渡されること |
| DEL-02 | 無効な日数  | `retentionDays = -1` を指定 | DAO の削除メソッドが呼び出されないこと                                   |
| DEL-03 | 全件削除   | `deleteAllLogs` を実行      | DAO の `deleteAll` が呼び出され、緊急ログファイルも削除されること               |

## 4. データ取得テスト (Get)
**目的:** ログの取得や件数監視が DAO と正しく連携しているかを検証する。

| ID     | テスト項目      | 検証内容                       | 期待結果                                    |
|:-------|:-----------|:---------------------------|:----------------------------------------|
| GET-01 | 総件数 Flow   | `getAuditLogCountFlow` の購読 | ログリストのサイズが整数値として流れてくること                 |
| GET-02 | 全件取得 (Raw) | `allLogsRaw` の実行           | DAO の `getAllLogsRaw` が呼び出され、リストが返されること |
