# テスト仕様書 - PersonRepository

- **対象テストコード:**
    - `app/src/test/java/jp/mydns/fujiwara/carememo/data/repository/PersonRepositoryTest.kt`

## 1. 概要
利用者の基本情報（姓名、ふりがな、生年月日、備考）に関するデータアクセス、永続化、および操作ログ記録の正確性を検証する。
特に、保存・更新に伴う監査ログの生成ルールと、生年月日の日付範囲を考慮した重複確認ロジックを対象とする。

## 2. 利用者操作テスト (CRUD)
**目的:** 利用者の保存および更新が DAO を介して正しく行われ、期待される詳細情報を含む監査ログが記録されることを検証する。

| ID     | テスト項目 | 検証内容               | 期待結果                                                          |
|:-------|:------|:-------------------|:--------------------------------------------------------------|
| CUR-01 | 新規登録  | `insertPerson` の実行 | DAO の `insert` が呼ばれ、`actionType="INSERT"` かつ詳細に姓名が含まれるログが残ること |
| CUR-02 | 情報更新  | `updatePerson` の実行 | DAO の `update` が呼ばれ、`actionType="UPDATE"` かつ詳細に姓名が含まれるログが残ること |

## 3. 重複確認ロジックテスト (Duplicate Check)
**目的:** 同姓同名・同生年月日の利用者を検索する際、時刻の微細な差を許容する日付範囲での検索が正しく行われることを検証する。

| ID     | テスト項目   | 検証内容                     | 期待結果                                                 |
|:-------|:--------|:-------------------------|:-----------------------------------------------------|
| DUP-01 | 既存利用者検索 | `findExistingPerson` の実行 | 指定された生年月日の 00:00:00 〜 23:59:59 の範囲が DAO の検索引数に渡されること |

## 4. データ取得テスト (Query)
**目的:** 利用者情報の取得が DAO と正しく連携しているかを検証する。

| ID     | テスト項目  | 検証内容                      | 期待結果                                    |
|:-------|:-------|:--------------------------|:----------------------------------------|
| GET-01 | 全利用者取得 | `getAllPersons` の Flow 購読 | 内部で DAO の `getAllPersons` が呼ばれること       |
| GET-02 | ID指定取得 | `getPersonById` の Flow 購読 | 指定した ID で DAO の `getPersonById` が呼ばれること |
