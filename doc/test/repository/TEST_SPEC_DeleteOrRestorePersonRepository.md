# テスト仕様書 - DeleteOrRestorePersonRepository

- **対象テストコード:**
    - `app/src/androidTest/java/jp/mydns/fujiwara/carememo/data/repository/DeleteOrRestorePersonRepositoryTest.kt`

## 1. 概要
利用者の「利用終了（論理削除）」、「復帰」、および「完全抹消（物理削除）」に伴う、全関連テーブルを横断するカスケード操作の正確性を検証する。
特に、トランザクション内での原子性と、監査ログが期待通り記録されることを対象とする。

## 2. カスケード論理削除・復帰テスト
**目的:** 利用者の状態変更に合わせて、紐付く全カテゴリのデータが同期して論理削除・復帰されることを検証する。

| ID     | テスト項目     | 検証内容                                 | 期待結果                                             |
|:-------|:----------|:-------------------------------------|:-------------------------------------------------|
| CAS-01 | カスケード論理削除 | 特定の利用者に対して `logicalDeletePerson` を実行 | 利用者および全関連レコードの `deleted_at` に同一のタイムスタンプがセットされること |
| CAS-02 | カスケード復帰   | 論理削除済みの利用者に対して `restorePerson` を実行   | 利用者および全関連レコードの `deleted_at` が全て `null` に戻ること     |
| CAS-03 | バッチ復帰     | 複数利用者に対して `restorePersonsBatch` を実行  | 指定した全ての利用者が復帰し、ログが人数分（またはバッチ単位で）記録されること          |

## 3. 物理削除（完全抹消）テスト
**目的:** 物理削除操作により、データがデータベースから完全に消去され、元に戻せない状態になることを検証する。

| ID     | テスト項目    | 検証内容                          | 期待結果                                                                                        |
|:-------|:---------|:------------------------------|:--------------------------------------------------------------------------------------------|
| PHY-01 | 個別抹消     | `permanentlyDeletePerson` の実行 | 指定した利用者の全データが物理削除され、**紐付く画像ファイルもストレージから消去されること**。ログに `actionType="PERMANENT_DELETE"` が残ること。 |
| PHY-02 | 全終了者一括抹消 | `deleteAllEndedPersons` の実行   | `deleted_at` がセットされている全ての利用者が抹消され、**紐付く全画像ファイルも消去されること**。有効な利用者は残ること。                       |

## 4. データ取得テスト
**目的:** アーカイブ状態のデータ取得が正しく行われることを検証する。

| ID     | テスト項目   | 検証内容                           | 期待結果                        |
|:-------|:--------|:-------------------------------|:----------------------------|
| GET-01 | 終了者一覧取得 | `getArchivedPersons` の Flow 購読 | 論理削除されている利用者のみがリストとして返されること |
