# テスト仕様書 - AppMaintenanceRepository

- **対象テストコード:**
    - `app/src/androidTest/java/jp/mydns/fujiwara/carememo/data/repository/AppMaintenanceRepositoryTest.kt`

## 1. 概要
アプリ全体のバックアップ、復元、データ消去、およびデータベース整合性修復ロジックの正確性を検証する。
複数の DAO やファイルシステムを横断する処理の原始性（トランザクション）と、データのクレンジングルールを対象とする。
また、各操作に伴う監査ログの記録が正しく行われることを検証する。

## 2. バックアップ・復元テスト (Backup & Restore)
**目的:** アプリ内の全 clinical データが、バックアップ・復元後もリレーションを含めて正しく維持されることを検証する。

| ID     | テスト項目             | 検証内容                                      | 期待結果                               |
|:-------|:------------------|:------------------------------------------|:-----------------------------------|
| BKR-01 | clinical データの完全復元 | 全ての臨床 Entity (Person, バイタル等) を含むバックアップの復元 | 全てのデータが元通り DB に登録され、リレーションが維持されること |
| BKR-02 | 利用者重複の自動救済        | 正規化により一意制約（姓名・生年月日）が衝突するデータのインポート         | メモに識別子が自動付記され、インポートが成功すること         |
| BKR-03 | 日時の正規化            | 生年月日の時刻が 00:00:00 以外であるデータのインポート          | UTC 00:00:00 に正規化されて保存されること        |
| BKR-04 | 服薬記録のクレンジング       | 不正なステータスコードを含む服薬記録のインポート                  | 不正レコードが除外されて保存されること                |
| BKR-05 | 復元時の監査ログ記録       | `replaceAllData` または `importData` 成功後のログ確認 | SUCCESS ログが記録されていること |

## 3. データ消去テスト (Clear Data)
**目的:** 指定された範囲のデータが完全に削除されることを検証する。

| ID     | テスト項目     | 検証内容                            | 期待結果                  |
|:-------|:----------|:--------------------------------|:----------------------|
| CLR-01 | 臨床データのみ消去 | `clearClinicalData` (内部用) 相当の動作 | 利用者や記録は消えるが、監査ログは残ること |
| CLR-02 | 全データ消去    | `clearAllData` の実行              | 監査ログを含む全てのテーブルが空になること |
| CLR-03 | 消去時の監査ログ記録 | `clearAllData` 成功後のログ確認 | SUCCESS ログが記録されていること（ログ消去後に記録されること） |

## 4. 整合性修復テスト (Inconsistency)
**目的:** 外部キー制約に違反した孤立レコード（親を失ったデータ）を検出し、安全に物理削除できることを検証する。

| ID     | テスト項目       | 検証内容                             | 期待結果                                       |
|:-------|:------------|:---------------------------------|:-------------------------------------------|
| INC-01 | 不整合の検出      | 親(Person)が存在しないレコードを意図的に挿入してスキャン | 対象レコードが `DatabaseInconsistency` (Enum型) として検出されること |
| INC-02 | 不整合のクリーンアップ | 検出された不整合リストを渡して削除実行              | 対象レコードが物理削除され、再スキャンで 0 件になること              |
| INC-03 | 修復時の監査ログ記録 | `cleanInconsistencies` 成功後のログ確認 | SUCCESS ログが記録されていること |

## 5. エクスポート・インポートテスト (Export & Import)
**目的:** 外部ストレージ (Uri) との ZIP ファイルを介したデータの受け渡しが正しく行われることを検証する。

| ID     | テスト項目       | 検証内容                      | 期待結果                                       |
|:-------|:------------|:--------------------------|:-------------------------------------------|
| EXI-01 | ZIP エクスポート  | 外部 Uri への ZIP 書き出し        | 指定パスに ZIP ファイルが生成され、中に JSON と写真フォルダが含まれること |
| EXI-02 | バージョン互換性エラー | 現在より新しいバージョンのバックアップをインポート | 内部エラーコード（"BACKUP_NEWER_THAN_APP" 等）を含む `IOException` がスローされること |
| EXI-03 | 写真ファイルの復元   | 写真を含むバックアップのインポート         | DB レコードの更新とともに、物理ファイルがアプリ領域に展開されること        |
| EXI-04 | 入出力時の監査ログ記録 | エクスポート・インポート成功後のログ確認 | それぞれ SUCCESS ログが記録されていること |
