# UI層テスト仕様書 - PersonEdit (利用者登録・編集)

## 1. コンポーネント単体テスト (PersonEditScreenContent)
**目的:** 入力項目の表示、バリデーションによる保存ボタンの活性・非活性状態、初期値の反映などを検証する。

| ID | テスト項目 | 検証内容 |
|:---|:---|:---|
| CP-01 | 初期表示（新規） | 全ての入力フィールドが空（またはデフォルト値）で表示されること。 |
| CP-02 | 初期表示（編集） | 引数で渡された利用者データが各フィールドに正しく埋め込まれていること。 |
| CP-03 | 必須項目の未入力バリデーション | 「姓」「名」「年」「月」「日」のいずれかが空の場合、保存ボタンが非活性であること。 |
| CP-04 | 必須項目の入力完了 | 「姓」「名」「年」「月」「日」の全てが入力された時、保存ボタンが活性化すること。 |
| CP-05 | 任意項目の入力 | 「せい」「めい」「同姓同名識別メモ」が空であっても、必須項目が埋まっていれば保存可能であること。 |
| CP-06 | カレンダー選択の切り替え | 和暦・西暦のセレクタを切り替えた際、年入力の表示が正しく更新されること。 |

## 2. 画面全体の挙動・結合テスト (PersonEditScreen)
**目的:** データの重複チェックロジックや、新規・更新の適切な使い分けを検証する。

| ID | テスト項目 | 検証内容 |
|:---|:---|:---|
| BH-01 | 重複データの警告表示 | 既存の別利用者と「姓・名・生年月日・識別メモ」の4条件が完全に一致するデータを入力して保存しようとした際、重複警告ダイアログが表示されること。 |
| BH-02 | 同姓同名・同年月日の許容 | 「姓・名・生年月日」が一致していても、「識別メモ」が異なれば重複とみなされず、保存（新規ならInsert、編集ならUpdate）が実行されること。 |
| BH-03 | 編集モードでの更新処理 | 編集モード（既存利用者の編集）において、識別メモのみを書き換えて保存した際、新規追加(Insert)ではなく、既存レコードの更新(Update)が行われること。 |
| BH-04 | 重複警告からのメモ編集 | 重複警告ダイアログで「編集を続ける」を選択した際、ダイアログが閉じ、「同姓同名識別メモ」へフォーカスが移動すること。 |
| BH-05 | キャンセル動作 | キャンセルボタンまたは戻る操作で、確認ダイアログが表示され、破棄を選択すると保存されずに画面が閉じること。 |

## 3. テスト用タグ (testTag) 定義
- `PersonEdit_LastName`: 姓入力フィールド
- `PersonEdit_FirstName`: 名入力フィールド
- `PersonEdit_LastNameKana`: せい入力フィールド
- `PersonEdit_FirstNameKana`: めい入力フィールド
- `PersonEdit_Memo`: 同姓同名識別メモ入力フィールド
- `PersonEdit_EraSelector`: 和暦・西暦セレクタ
- `PersonEdit_BirthYear`: 年入力フィールド
- `PersonEdit_BirthMonth`: 月入力フィールド
- `PersonEdit_BirthDay`: 日入力フィールド
- `PersonEdit_SaveButton`: 保存ボタン
- `PersonEdit_CancelButton`: キャンセルボタン
- `PersonEdit_DuplicateDialog`: 重複警告ダイアログ

## 4. 実装状況と未実施項目の理由
今回のUIテスト実装（`PersonEditScreenTest.kt`）において、一部の項目は以下の理由により ViewModel ユニットテスト側での検証、あるいは他項目との統合検証とした。

| ID | テスト項目 | 検証の考え方 |
|:---|:---|:---|
| CP-05 | 任意項目の入力 | `CP-04` (必須項目の入力完了) において、フリガナやメモが空の状態でも保存ボタンが活性化することを同時に確認しているため、単独のテストは省略した。 |
| BH-02 | 同姓同名・同年月日の許容 | データの挿入(Insert)かエラーかの判定は ViewModel の純粋なロジックに依存するため、`PersonEditViewModelTest` にて DB モックを用いた厳密な検証を行っている。 |
| BH-03 | 編集モードでの更新処理 | 既存レコードの ID を維持して更新(Update)が行われるかどうかの判定は、ViewModel 側のロジック責務であるため、`PersonEditViewModelTest` にて検証済み。 |
