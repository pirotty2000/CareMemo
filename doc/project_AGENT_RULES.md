# CareMemo AI開発ルール (AGENT_RULES.md)

このドキュメントは、AI Agent が CareMemo のソースコードを修正・追加・レビューする際の行動規範と実装ルールを定義します。
プロジェクト全体のパッケージ構造やファイル構成については、`project_structure.md` を参照してください。

---

# 1. 開発の基本指針

- **最小修正**: 依頼内容以外は変更しない。不要な設計変更、命名変更、リファクタリング、フォルダ整理を禁止する。
- **既存設計の尊重**: 既存のアーキテクチャや命名規則を優先する。変更が必要な場合は理由と影響範囲を説明し、承認を得ること。
- **推測の禁止**: 仕様が曖昧な場合は実装せず、必ず質問すること。
- **動作確認**: 修正完了時は「修正ファイル」「共通部品への影響」「動作確認が必要な画面」を報告すること。

---

# 2. アーキテクチャと実装パターン

### ViewModel の二段構え (Dual-ViewModel)
利用者詳細画面等では、以下の連携パターンを遵守してください。
- `PersonDetailViewModel`（共通フレームワーク）と、カテゴリごとの「専門 ViewModel」を併用する。
- `PersonDetailViewModel` が持つ `personId` を Composable 経由で専門 VM の `loadPerson(id)` へ伝達し、コンテキストを同期する。

### ビジネスルールの集約 (AppThresholds)
- 入力制限（桁数）、バリデーションロジック、正常/異常の閾値判定などは、個別のクラスに分散させず、必ず **`data/AppThresholds.kt`** に集約する。

### 状態管理とパフォーマンス
- **ブランキング（チラつき）抑制**: IDに基づくデータロード時、初期値のセットに `LaunchedEffect` を使用しない。`remember(id) { ... }` 等で初期状態を制御すること。
- **リストの安定化**: ViewModel から取得したリストを加工して渡す際は、`remember(records)` でインスタンスを安定化させ、不要な再コンポーズを防ぐ。
- **入力データの保護**: 入力・編集画面では `BackHandler` を実装し、未保存の変更がある状態で戻る操作をした場合は必ず破棄確認ダイアログを表示する。

### 利用者コンテキストの確実な切り替え
- `loadPerson(id)` の開始時に、古いデータを即時クリア（nullセット等）し、ロード用コルーチン（Job）をキャンセルしてから新しい取得を開始すること。

---

# 3. セキュリティ・バイ・デフォルト

- **完全オフライン**: 原則としてインターネット接続権限（INTERNET）を付与しない。
- **プライバシー保護**: 個人情報のマスキング機能は初期状態で「ON」とする。
- **生体認証**: セキュリティ設定の変更や機密情報の表示には、デバイスの生体認証または端末ロック解除を必須とする。

---

# 4. 操作ログ (監査ログ) の実装ガイド

データの変更（CRUD）を伴う操作は必ず記録してください。
- **Repository**: `AuditLogRepository` を経由して実行する。
- **ViewModel**: Repository のメソッド呼び出し時に、論理的な「画面名（日本語）」と「操作内容」を引数として渡す。
- **actionType**: `INSERT`, `UPDATE`, `DELETE`, `LOGICAL_DELETE`, `RESTORE` を適切に使い分ける。

# 6. コーディング規約・禁止事項

- **規約**: Booleanは `is~`, `has~`, `can~` とする。`StateFlow` を優先し、`collectAsStateWithLifecycle` を使用する。
- **禁止**: `TODO` 追加、仮実装、未使用コードの放置、依頼されていない最適化。
