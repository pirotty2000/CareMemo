# コーディング規約

## 1. Modifier の扱い

- **引数の定義**: すべての Composable は、原則として `modifier: Modifier = Modifier` を引数に持ちます。
- **[MUST] ルート要素への適用**: 外部から渡された `modifier` は、最外位要素にのみ適用してください。
- **[MUST] 二重余白の禁止**: `Content` コンポーネント自身がルート要素に `padding()` を付与することは原則禁止です。外側の余白管理は `Screen` 層が担当します。
- **純粋性の維持**: 外部から渡された `modifier` に対し、内部都合で `fillMaxSize()` 等を勝手に連結しないでください（呼び出し側の意図を優先）。

## 2. リソース管理 (strings.xml)

- **文言の集約**: ユーザーの目に触れる全文字列を `strings.xml` に定義してください。
- **リソース ID 命名**: `common_`, `health_`, `settings_item_` 等の適切な接頭辞を使用してください。
- **[MUST] Mapper の責務**: `ui/mapping` 層は、文字列そのものではなく **リソース ID (`Int`)** を返してください。

## 3. タイポグラフィと特殊文字

- **特殊文字の利用**: `©` (&#169;), `–` (&#8211;), `…` (&#8230;) 等の適切な実体参照を使用してください。
- **プレースホルダ**: 翻訳を考慮し、位置指定子（`%1$d`, `%1$s`）を必ず明示してください。
