## 2026/07/20: Pre-Phase - ViewModel 構造改善計画の策定

### 概要
ViewModel の肥大化と状態管理の複雑化を解消するため、アーキテクチャの基本原則を再定義。

### 課題 (Problems)
- **ViewModel の責務過剰**: UI 状態の管理、イベントハンドリング、複雑なビジネスロジックが単一の ViewModel に集中し、テスト容易性が低下していた。
- **状態不整合の懸念**: 非同期処理や連続タップによる Race Condition への対策が不十分だった。
- **拡張性の限界**: 新しい記録項目の追加時に大量の条件分岐（if-else）が発生する構造だった。

### 実施内容 (Actions)
- **設計原則 (CareMemo Principles) の確立**:
    - **Single Source of Truth (SSOT)**: `uiState` の一元管理と、UI への加工済みデータの供給を徹底。
    - **State vs Event の分離**: 表示状態（State）と一過性の動作（Event）を明確に区別。
    - **非同期制御の標準化**: `safeLaunch` 等の共通基盤による例外保護と、最新リクエスト優先（Latest Result Only）の徹底。
- **フェーズ制ロードマップの策定**: 本計画で定義された未完了タスクは、以降の Phase 3〜6 へ統合・継承された。

## 2026/08/09: Phase 2 - 次世代品質向上プロジェクト (アーキテクチャ刷新)

### 概要
Jetpack Compose / Material 3 の最新ベストプラクティスに基づき、アプリの堅牢性と保守性を抜本的に高めるための基盤刷新を実施。

### 課題 (Problems)
- **脆弱なナビゲーション**: 文字列ベースのルート定義により、型安全性が欠如し、画面遷移の保守が困難だった。
- **ViewModel の依存性**: プロセス死からの復帰耐性が弱く、UI側（LaunchedEffect）でのデータロードに依存していた。
- **パフォーマンスの懸念**: リストの再コンポーズが Compose コンパイラによって最適化されていなかった。
- **UI実装の非統一**: Modifier の伝播ルールやプレビュー環境が未整備で、実装品質にバラつきがあった。

### 実施内容 (Actions)
- **Type-safe Navigation の導入**: 文字列ルートを廃止し、`@Serializable` なオブジェクトによる型安全な遷移へ移行。
- **ViewEvent の一元化**: 画面遷移やトースト表示等のイベントを ViewModel 発行の `sealed interface` として一元管理。
- **SavedStateHandle の活用**: ViewModel が自律的に引数を取得する構造へ変更し、プロセス死耐性を向上。
- **不変コレクション (ImmutableList) の採用**: `kotlinx.collections.immutable` を導入し、UI状態の安定性を確保。
- **Modifier ルールの厳格化**: コンポーネントの再利用性と予測可能性を高めるための伝播ルールを全画面に適用。
- **PreviewParameterProvider の導入**: 正常・異常・空状態などの多様な UI 状態を網羅的にプレビューできる環境を構築。
- **リソース ID への文言集約**: アプリ内の全ハードコード文字列を `strings.xml` へ移行。

## 2026/08/14: Phase 3 - UI 境界の整合性と最適化

### 概要
UI と ViewModel の境界における責務を整理し、ビジネスロジックの漏れ出しを解消。

### 課題 (Problems)
- **責務の混在**: `derivedStateOf` を用いたビジネスロジック（変更検知やバリデーション）が Composable 内に存在し、テストが困難だった。
- **不変コレクションの過剰適用**: Logic レイヤーまで `ImmutableList` に依存しており、純粋なロジック層の柔軟性が損なわれていた。
- **プラットフォーム機能の不安定性**: 生体認証等の Activity 依存機能の呼び出しルールが不明確だった。

### 実施内容 (Actions)
- **ロジックの ViewModel 集約**: `isChanged`（変更検知）やバリデーション判定を Composable から ViewModel へ移動。
- **UI 境界の整理**: `ImmutableList` への変換を ViewModel (UI境界) に限定し、Logic/Repository 層は標準の `List` を使用するように修正。
- **Activity 委譲ルールの適用**: 生体認証や `ActivityResult` API 等のプラットフォーム機能を `MainActivity` へ適切に委譲。
- **テスト戦略の強化**: 画面遷移を跨ぐデータ整合性を検証するシナリオテスト、および入力競合を検出するインクリメンタルテストを導入。

## 2026/08/15: Phase 4 - アーキテクチャ境界の純粋化

### 概要
レイヤー間の依存関係ルール（Dependency Matrix）を厳格に適用し、モジュール間の結合度を低減。

### 課題 (Problems)
- **依存関係の逆転**: Repository が Logic に依存したり、ViewModel が Android Context を保持したりする規約違反が発生していた。
- **セキュリティ境界の甘さ**: アプリ起動時や重要操作時（データ出力）の認証チェックが不十分だった。
- **複雑な仕様**: バックグラウンド移行時のロックタイマー設定が保守コストを増大させていた。

### 実施内容 (Actions)
- **プラットフォーム依存の排除**: ViewModel から `Context` や `BiometricManager` への直接参照を排除。
- **Repository の純粋化**: `AppMaintenanceRepository` 等から Logic への依存を排除し、永続化のみを担当する構造へ修正。
- **リポジトリ設計の標準化 (ADR #8)**: 子テーブルのリポジトリにおける ID 生成と保存フラグの扱いを統一。
- **セキュリティ強化**: アプリ起動時のデフォルト・ロック、および PDF 出力等の重要操作時の再認証（Step-up Auth）を導入。
- **仕様の単純化**: ロックタイマーを廃止し、バックグラウンド遷移時の「即時ロック」へ仕様を一本化。

## 2026/08/21: Phase 5 - プロジェクト適合性調査

### 概要
全コンポーネントを対象としたルール適合状況の総点検と、発見された不整合の解消。

### 課題 (Problems)
- **監査ログの記録漏れ**: インポート操作や設定変更、物理削除失敗時のログが不足していた。
- **アーキテクチャ違反**: リポジトリが UI リソース (`R.string`) に依存したり、UI 部品が ViewModel に直接依存したりしていた。
- **リソースリーク**: 利用者の物理削除時に、紐付く画像ファイルが削除されずに残る不備があった。

### 実施内容 (Actions)
- **監査ログの網羅性向上**: 破壊的操作や重要設定の変更時における監査ログ記録を徹底。
- **UI リソース依存の解消**: `DatabaseInconsistency` 等の理由定義を UI リソースから切り離し、ドメインモデルとして定義。
- **物理削除プロセスの修正**: 利用者抹消時に画像ファイルも確実に削除されるよう Repository を修正。
- **時刻取得の統一**: `System.currentTimeMillis` の使用を廃止し、`Instant` への取得ロジックに統一。
- **UI コンポーネントの Stateless 化**: `PdfExportActionHandler` 等から ViewModel 依存を排除し、呼び出し側から制御する設計へリファクタリング。

## 2026/08/22: Phase 6 - 監査ログの強化とエクスポート機能

### 概要
例外処理の可視化と、外部メンテナンス用のログ抽出機能の実装。

### 課題 (Problems)
- **隠れたエラーの黙殺**: ファイル操作や DB の自動再作成などの重要イベントが `try-catch` で握りつぶされ、証跡が残っていなかった。
- **ログの閉鎖性**: 監査ログがアプリ内の DB に閉じており、トラブルシューティング時に外部から確認できなかった。

### 実施内容 (Actions)
- **監査ログ・エクスポートの実装**: 監査ログを JSON および CSV 形式で出力し、パスワード付き ZIP としてエクスポートする機能を実装。
- **例外処理の再整理**: `Ignored` とされていた例外（IOエラー、DB再作成等）をキャッチし、監査ログに記録するよう修正。
- **SystemEmergencyLogger の新設**: DB が破損・ロックされている場合でも、ファイルシステムへ緊急ログを記録する仕組みを導入。
- **重大イベントの捕捉**: SQLCipher のパスワード不一致による DB 再作成や、カメラデバイスのエラー等を確実にロギング。
- **マッパーの拡充**: `FeatureNameMapper` を整備し、リポジトリ層等の内部機能名も UI 上で正しく表示されるよう改善。
