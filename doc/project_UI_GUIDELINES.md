# CareMemo UI設計ガイドライン (UI_GUIDELINES.md)

このドキュメントでは、CareMemo の UI/UX 設計、および画面デザインの共通ルールを定義します。
具体的なファイル構成やコンポーネントの依存関係については、`project_structure.md` を参照してください。

---

# 1. UI設計思想

CareMemo では、画面を単なるテーブル単位ではなく「ユーザーの振る舞い」に基づいて設計します。

- **(A) 数値時系列**: 血圧、体重、血糖値など、推移をグラフ化し、推移を確認するもの。
- **(B) テキスト時系列**: 所見メモ、写真など、日常の出来事を時系列で記述するもの。
- **(C) 服薬マトリックス**: 日付 × 時間枠（朝・昼・夕・寝る前）の状況を管理するもの。

新規画面の追加時は、既存のいずれの振る舞いに該当するかをまず検討してください。

---

# 2. 画面構成の標準 (マルチペイン対応)

利用者詳細画面（A/B/C共通）は、デバイスサイズに応じて最適化される構造を維持します。
実装時のファイル構成ルール（Phone/Tablet/Contentの分離）については、`project_structure.md` の「詳細画面の設計原則」に従ってください。

---

# 3. 入力体験の統一 (AppTextField)

標準の `OutlinedTextField` は使用せず、共通基盤である `AppTextField` シリーズを使用し、以下の挙動を徹底してください。

### 基本ルール
- **カーソル制御**: タップ（フォーカス取得）時は、既存の値を保持したまま**カーソルを末尾へ自動移動**させる。
- **自動フォーカス**: 年月日などの固定桁数（maxLength）到達時、または IME Next 押下時に、次の項目へ自動的にフォーカスを移動させる。
- **属性による最適化**: `INTEGER`, `DECIMAL`, `TEXT` 等のタイプ指定により、適切なキーボード、バリデーション、IMEアクションを自動適用する。

---

# 4. ダイアログの標準化 (AppDialog)

意思決定を求めるダイアログは、共通基盤である `AppDialog` を使用し、ユーザーの視線誘導を統一します。

### ボタン配置と色分け
- **右下 (Primary/Positive)**: 確定・実行アクション。常に「塗りつぶしボタン」を使用。
    - **SAVE**: 保存・登録。Primary色（テーマ主色）。
    - **DELETE**: 削除・破棄。Error色（警告赤）。
    - **ACTION**: 出力・実行。Tertiary色（アクセント色）。
- **左下 (Dismiss/Negative)**: キャンセル・戻る。常に「テキストボタン」を使用し、視覚的な重みを下げる。

### レイアウト
- コンテンツを `AppDialogContent` でラップし、長文時でもタイトルとボタンエリアを固定したまま中身だけをスクロールさせる。

---

# 5. 配色とプライバシー

### 配色ルール
- `MaterialTheme.colorScheme` を利用し、固定色（Color.Red等）の直接指定を避ける。
- **正常/情報**: `onSurfaceVariant`（グレー系）。情報をミュートして重要シグナルの埋没を防ぐ。
- **注意/予備群**: オレンジ系（ライト：#E65100 / ダーク：#FFB74D）。
- **異常/警告**: `error`（赤系）。

### マスキング (個人情報保護)
- 氏名等の表示には `Person` クラスの `getMaskedName()` / `getMaskedFurigana()` を必ず使用する。
- **PDF出力時は、アプリの表示設定に関わらず、常にマスキング（伏せ字）を適用した状態で出力する。**
