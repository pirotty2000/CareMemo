# アラート・レポート機能 仕様定義書 (Alert Report Specification)

## 1. 概要
保存された健康データから異常値や急激な変化を抽出し、一覧表示する機能です。
見逃されがちなバイタルの異常や健康状態の悪化を早期に発見することを目的とします。

## 2. アラート判定基準

### 2.1. 基本異常値判定 (`AppSpecifications` に準拠)
`HealthLogic` で定義されている判定基準に基づき、以下のレベルをアラート対象とします。

| 項目       | カテゴリ | アラートレベル     | 判定基準 (AppSpecifications参照) |
|:---------|:-----|:------------|:---------------------------|
| 血圧 (上/下) | バイタル | **ALERT**   | 高血圧 (140/90 以上)            |
|          |      | **WARNING** | 低血圧 (100/60 未満)            |
| 脈拍       | バイタル | **ALERT**   | 頻脈 (100 以上)                |
|          |      | **WARNING** | 徐脈 (50 以下)                 |
| 酸素飽和度    | バイタル | **ALERT**   | 90% 以下                     |
| 体温       | バイタル | **ALERT**   | 発熱 (37.5℃ 以上)              |
|          |      | **WARNING** | 低体温 (35.0℃ 未満)             |
| 血糖値      | 血糖   | **ALERT**   | 糖尿病型 (126 以上)、低血糖 (70 未満)  |
|          |      | **WARNING** | 予備群 (110 以上)               |
| HbA1c    | 血糖   | **ALERT**   | 糖尿病型 (6.5 以上)              |
|          |      | **WARNING** | 予備群 (5.6 以上)               |
| BMI      | 体格   | **ALERT**   | 肥満(3度)以上 (35 以上)           |
|          |      | **WARNING** | 肥満(2度) (30 以上)             |

### 2.2. 特殊アラート (時系列比較)
単一のデータでは異常とされない範囲でも、短期間の変化に注目して抽出します。

| 項目   | 判定条件                               | レベル       | メッセージ例            |
|:-----|:-----------------------------------|:----------|:------------------|
| 体重減少 | 時系列的に一つ前のデータと比較し、**3.0kg以上減少**している | **ALERT** | 急激な体重減少 (-X.X kg) |

## 3. アラート抽出仕様

### 3.1. 抽出対象範囲
- **基本原則**: 各利用者の**「直近のデータ（最新の1件）」**のみを判定対象とします。
    - 古い異常値が解消（最新値が正常）されている場合、レポートには表示されません。
- **抽出対象期間**: 制限なし。全期間のデータの中から最新のものを抽出します。
- **体重減少の特例**: 日時に関わらず、「最新のデータ」とその「一つ前のデータ」を比較して判定します。

### 3.2. 抽出対象データ
- 身長・体重 (`HeightAndWeight`)
- バイタル (`BpAndPulse`)
- 血糖・HbA1c (`GlucoseAndHbA1c`)

## 4. レポート画面仕様 (AlertReportScreen)

### 4.1. 表示内容 (リスト項目)
- 利用者名 (マスク対応)
- 発生日時 (記録日時)
- 項目名 (例: 血圧、体重)
- 値と単位
- 警告メッセージ / 判定結果
- 重大度インジケータ (ALERT: 赤, WARNING: 黄)

### 4.2. フィルタ・ソート
- **フィルタ**: カテゴリ別（すべて、バイタル、体重、血糖）
- **ソート**: 日時の降順（新しい順）を標準とする。

### 4.4. 利用者一覧での通知 (MainScreen / UserListItem)
レポート画面へ誘導するため、利用者一覧の各カード上でアラートの有無を通知します。

#### A. アラートバッジの表示
- `CategoryBadges` の空きスペース（3段目右側）を活用し、異常値がある場合に専用のバッジ（「！」）を表示します。
- 色：重大度に応じたアクセントカラー（赤系）。

#### B. 背景色の変更（優先表示）
- 異常値が存在する利用者のカード背景色を変更し、視認性を高めます。
- **背景色の優先順位**:
    1. **アラート通知**: 最優先で適用。重大度（Alert/Warning）によって色を分ける可能性があります（要精査）。
    2. **誕生日（当日）**: アラートがない場合のみ適用。
- **変更点**: これまで実施していた「誕生日が近い（近日）」利用者への背景色変更は廃止し、アラート通知にそのリソースを譲ります。（※ケーキアイコンによる通知は継続）

## 5. 監査ログ
以下のタイミングで監査ログを記録します。
- レポート生成（スキャン）開始時
- レポートから詳細画面への遷移時

## 6. 非機能要件
- データ量が多い場合でも UI をブロックしないよう、抽出処理は `Dispatchers.Default` 等で非同期に実行する。
- `Structural / Operation` 状態分離に基づき、スキャン中はインジケータを表示する。
