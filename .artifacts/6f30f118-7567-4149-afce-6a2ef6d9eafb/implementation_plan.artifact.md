# 所見メモ写真追加後のナビゲーション改善計画

写真追加後に「キャンセル」ボタンしか有効なアクションがないように見える問題を解決し、ユーザーに安心感を与えるためのUI改善を行います。

## ユーザーレビューが必要な事項

- **写真の保存タイミング**: 写真は撮影・選択直後のプレビュー画面で「保存」した時点で確定されます。この改善後もその仕様は維持されます。
- **戻るボタンの挙動**: テキストに変更がない場合、ヘッダーの「←」および下部の「戻る」ボタンは確認ダイアログなしで即座に画面を閉じます。テキストに変更がある場合のみ、従来通り破棄確認ダイアログを表示します。

    - `ConditionRecordEditForm` 呼び出し時に `uiState.isChanged` を渡すように拡張します。
- **`ConditionRecordEditForm`**:
    - 引数に `isChanged: Boolean` を追加します。
    - タイトル部分を `Row` に変更し、左側に `IconButton` (ArrowBack) を配置します。
    - 下部の `OutlinedButton` のテキストを `isChanged` の状態に応じて `common_cancel` (キャンセル) と `common_back` (戻る) で切り替えます。

## 検証プラン

### 手動確認
1. **既存レコードの編集**:
    - テキストを変更せず、写真だけを追加する。
    - ボタンが「戻る」に変わっていることを確認する。
    - ヘッダーの「←」または「戻る」ボタンをタップし、ダイアログなしで閲覧モードに戻ることを確認する。
    - 追加した写真が保持されていることを確認する。
2. **新規レコードの作成**:
    - 写真だけを追加する。
    - 「戻る」をタップし、一覧画面に戻ることを確認する。
    - （仕様通り）所見レコードは作成されず、写真は「未割り当て」状態になることを確認する。
3. **変更保護の維持**:
    - テキストを入力（変更あり状態）にする。
    - ボタンが「キャンセル」のままであることを確認する。
    - 「←」または「キャンセル」をタップし、破棄確認ダイアログが表示されることを確認する。
